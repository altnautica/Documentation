ADOS is an open-source software stack for drones. It covers the aircraft, the ground and the fleet: an agent on the drone's companion computer, the same agent on a ground station for long-range video, a ground control station that runs in your browser, and the extensions, SDKs and AI tooling built on them.

## How they fit together

The flight controller runs the autopilot firmware. The companion computer runs the Drone Agent. On the ground, a small single-board computer runs the Ground Agent. Mission Control runs in your browser, the desktop app or the Android GCS.

```mermaid
flowchart LR
    subgraph Drone
        FC[Flight controller<br/>ArduPilot / PX4 / Betaflight / iNav]
        CAM[Camera]
        SBC[Companion computer<br/>Drone Agent]
        RADIO_TX[WFB-ng radio]
    end

    subgraph Ground
        RADIO_RX[WFB-ng radio]
        GS[Ground station<br/>Ground Agent]
    end

    subgraph You
        BROWSER[Browser<br/>Mission Control]
        PHONE[Phone or tablet]
        MONITOR[HDMI monitor]
    end

    FC <-->|MAVLink / MSP| SBC
    CAM -->|USB / MIPI CSI| SBC
    SBC -->|H.264 / H.265 video| RADIO_TX
    RADIO_TX -.->|WFB-ng| RADIO_RX
    RADIO_RX --> GS
    GS -->|Wi-Fi AP / USB tether| BROWSER
    GS -->|Wi-Fi AP| PHONE
    GS -->|HDMI| MONITOR
    SBC -->|LAN or cloud relay| BROWSER
```

<Note>
You do not need every product at once. Mission Control works on its own with a USB cable to your flight controller. The Drone Agent works on its own over Wi-Fi, Ethernet or a cellular modem. The Ground Agent is only needed for long-range WFB-ng video.
</Note>

## Who it is for

**FPV builders and pilots.** You already have a drone and want configuration tools, mission planning and a ground control station that runs in your browser.

**Researchers and engineers.** You need a programmable platform with a REST API, SDKs in Python, Rust and TypeScript, and AI access over MCP.

**Operators.** You run mapping, inspection or agriculture missions and need planning, fleet telemetry and room to customise.

**Students and educators.** You want to learn how drones work at every layer, in code you can read.

**Hardware integrators.** You build drone hardware and want an open software stack on it. The agent describes each supported board with a board profile; see [Supported hardware](/drone-agent/supported-hardware).

## What each product does

### Mission Control
- Connects to ArduPilot, PX4, Betaflight or iNav over USB (WebSerial), the LAN or the cloud relay
- Flight controller configuration panels and calibration wizards
- Mission planning with pattern generators, 3D mission simulation, geofences and rally points
- A per-node cockpit with live video, gamepad and HOTAS control
- Firmware flashing from the Flash Tool
- Demo mode with a simulated fleet, so you can try it with no hardware

### Drone Agent
- One-line install on 64-bit ARM (aarch64) Linux boards; x86_64 Linux uses a locally built installer, and macOS installs as a workstation
- Detects the board and the flight controller
- Camera to H.264 or H.265 video over WFB-ng or WebRTC
- A REST API and browser dashboard on port 8080, served by a native Rust front
- A [terminal dashboard](/drone-agent/tui-dashboard) and the `ados` CLI
- Signed extensions with SDKs for Python, Rust and TypeScript
- Updates with `ados update`

### Ground Agent
- Same install script, with `--profile ground_station`
- Receives WFB-ng video and serves it to browsers over WebRTC
- Wi-Fi access point and USB tether for laptops and phones
- Physical controls: OLED and buttons, plus an optional touch LCD
- HDMI kiosk mode for field use with a monitor and gamepad
- Mesh relay and receiver roles (distributed receive) for multi-node ground networks
