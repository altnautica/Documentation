A drone running ADOS has two computers on board. The **flight controller** runs the autopilot: motors, stabilization, GPS and sensors. The **companion computer** runs the Drone Agent, which handles video, the radio link, the cloud relay and the REST API. On the ground, Mission Control runs in your browser, the desktop app or the Android GCS. For long-range video, a ground station running the Ground Agent sits between the radio and your devices.

## Ways Mission Control reaches a drone

Mission Control shows which path it is using for each node: **Direct FC**, **Direct · LAN**, a WFB path through a ground station, or **Cloud relay**.

| Path | How it works | Use it for |
|---|---|---|
| Direct FC | A USB cable from your computer to the flight controller. Mission Control speaks MAVLink or MSP over WebSerial. No agent needed. | Bench work, configuration, calibration, firmware flashing |
| Direct · LAN | Your computer and the agent share a network (Wi-Fi, Ethernet or USB tether). Mission Control uses the agent's REST API and MAVLink WebSocket, and plays video over WebRTC. | Field work at short range, development |
| WFB via a ground station | The drone's radio sends video over WFB-ng to a ground station. Your devices join the ground station's Wi-Fi access point or USB tether. | Long-range flights |
| Cloud relay | The agent connects out to an MQTT broker. Mission Control reaches it from anywhere. | Remote monitoring and fleet work over cellular or any internet uplink |

## MAVLink

Flight controllers running ArduPilot and PX4 speak MAVLink; Betaflight and iNav speak MSP. On the drone, the agent's native Rust MAVLink router owns the serial link to the flight controller, sends its own heartbeat as an onboard controller, and fans MAVLink out to Mission Control and to the other agent services. Mission Control parses MAVLink and MSP frames itself in the browser. See [MAVLink protocol](/architecture/mavlink-protocol).

## Video

The agent captures a USB or MIPI CSI camera and encodes H.264 or H.265. The stream goes out over WFB-ng to a ground station, which serves it to browsers over WebRTC (WHEP). Over the cloud, video is negotiated through MQTT signaling. See [Video stack](/architecture/video-stack) for every hop and the latency figures.

## Cloud relay

The cloud relay is off by default: a fresh node runs **Local only**. When you choose **Altnautica cloud** or **Self-hosted**, the agent:

- relays raw MAVLink frames over MQTT on `ados/{id}/mavlink/tx` (flight controller to Mission Control) and `ados/{id}/mavlink/rx` (Mission Control to flight controller), with the same shape for MSP on `ados/{id}/msp/tx` and `ados/{id}/msp/rx`. Mission Control decodes these frames directly, so telemetry arrives at the flight controller's own stream rate.
- posts a status heartbeat over HTTPS every 5 seconds and polls for queued commands every 5 seconds.

See [Cloud infrastructure](/architecture/cloud-infrastructure) for the full topic list, and [Self-hosting](/developers/self-hosting/overview) to run the cloud yourself.

## Ground stations

A ground station is the same agent installed with the `ground_station` profile. The profile is chosen at install time, not detected. It receives WFB-ng video and serves it to laptops and phones over its Wi-Fi access point or USB tether, and to an HDMI monitor in kiosk mode. See [Node profiles](/getting-started/node-profiles) and the [Ground Agent overview](/ground-agent/overview).

For the full component map, see [System overview](/architecture/system-overview).
