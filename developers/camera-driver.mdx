A `CameraDriver` reads frames from a physical or networked imaging device. Visible, thermal, depth and multi-spectral devices share this interface.

The worked `CameraDriver` subclass is `LeptonUvcDriver` in the FLIR Lepton plugin ([`extensions/thermal-camera-flir-lepton-usb`](https://github.com/altnautica/ADOSExtensions/tree/main/extensions/thermal-camera-flir-lepton-usb), file `agent/src/altnautica_thermal_camera/driver.py`). The plugin is a development preview: capture needs a libuvc backend the agent does not ship, so it is not published.

## The interface

```python
from ados.sdk.drivers.camera import (
    CameraDriver,
    CameraCandidate,
    CameraCapabilities,
    CameraSession,
    FrameBuffer,
)

class MyCameraDriver(CameraDriver):
    async def discover(self) -> list[CameraCandidate]:
        ...

    async def open(self, candidate, config) -> CameraSession:
        ...

    async def close(self, session) -> None:
        ...

    def capabilities(self, session) -> CameraCapabilities:
        ...

    async def frame_iterator(self, session):
        # async generator yielding FrameBuffer
        ...

    async def set_param(self, session, param, value) -> None:
        ...
```

## Candidates

`CameraCandidate` carries `driver_id`, `device_id`, `label`, `bus`, and optional `vid_pid` and `metadata`:

```python
CameraCandidate(
    driver_id="com.example.my-camera",
    device_id="usb-1.2.3",
    label="MyCorp ThermalCam on USB 1.2.3",
    bus="usb",
    vid_pid=(0x1e4e, 0x0100),
)
```

Keep `device_id` stable across reboots when the bus can produce a stable identifier (USB serial, CSI lane, RTSP URL). Where that is impossible (raw V4L2 indexing), produce an id that is at least deterministic within one boot.

## Capabilities

Returned once per session, after `open`:

```python
CameraCapabilities(
    radiometric=True,
    bit_depth=14,
    width=160,
    height=120,
    fps=8.7,
    pixel_format="Y16",
    streaming_protocol="uvc",
    color_spaces=[],
    has_audio=False,
)
```

`radiometric=True` means every pixel encodes a temperature and `FrameBuffer.radiometric_k` carries the per-pixel Kelvin matrix.

## Frame buffers

```python
FrameBuffer(
    timestamp_ns=ns,
    sequence=seq,
    width=160,
    height=120,
    pixel_format="Y16",
    data=memoryview(raw_bytes),
    radiometric_k=memoryview(temp_k_matrix),
    metadata={"shutter_open": True},
)
```

`data` is a `memoryview` so your consumers can avoid copies. Put driver-specific fields under `metadata`.

## Opening the driver from your plugin

Your plugin constructs the driver and drives it. This is the shape of the FLIR Lepton plugin's `on_start`:

```python
class Plugin:
    async def on_start(self, ctx):
        self.driver = MyCameraDriver(self.backend_factory())
        candidates = await self.driver.discover()
        if not candidates:
            await ctx.events.publish("com.example.my-camera.status", {"state": "no_device"})
            return
        self.session = await self.driver.open(candidates[0], {})
        self.task = asyncio.create_task(self.pump(ctx))

    async def pump(self, ctx):
        async for frame in self.driver.frame_iterator(self.session):
            ...  # process, then publish what your GCS half shows

    async def on_stop(self, ctx):
        self.task.cancel()
        await self.driver.close(self.session)
```

Declare the bus capability the device needs (`hardware.usb.uvc`, `hardware.camera.csi` or `hardware.usb`). The full table is on [Driver layer](/developers/driver-layer#manifest-permissions).

## Testing without hardware

Inject a mock backend that produces synthetic frames through the driver's constructor. The FLIR Lepton plugin ships `MockUvcBackend` in `agent/tests/mock_backend.py` for exactly this. See [Hardware testing](/developers/hardware-testing) for the pattern.
