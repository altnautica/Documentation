This walkthrough builds `com.example.hello-panel`, the smallest useful
plugin: a GCS-only tab on a drone's node-detail panel that subscribes to
the host's normalized battery telemetry and prints the pack voltage.
There is no agent half. The plugin runs entirely inside Mission Control,
in a sandboxed iframe, and reads telemetry the drone already publishes.

By the end you have a manifest the host accepts, a bundle that mounts, a
unit test that runs without Mission Control, and a signed `.adosplug`
archive.

<Note>
Battery health (per-cell analysis, sag detection, time-to-reserve and
anomaly alerts) is built into the drone agent. See
[Battery health](/drone-agent/battery-health). This tutorial uses the
battery topic only because every drone publishes it.
</Note>

## Prerequisites

- Node.js 20+ and pnpm 9+.
- A Mission Control install with a paired drone (or demo mode) to see
  the tab.

## 1. Scaffold

The SDK and the `create-ados-plugin` scaffolder live in the
[`altnautica/ADOSExtensions`](https://github.com/altnautica/ADOSExtensions)
monorepo. Develop the plugin as a workspace member there:

```sh
git clone https://github.com/altnautica/ADOSExtensions.git
cd ADOSExtensions
pnpm install

node packages/create-ados-plugin/bin/cli.mjs \
  --target extensions/hello-panel \
  --id com.example.hello-panel \
  --half gcs-only \
  --author "Your Name"
```

The GCS-only template lays out:

```
extensions/hello-panel/
├── manifest.yaml
├── package.json
├── README.md
├── CHANGELOG.md
├── locales/en.json
└── gcs/
    ├── package.json
    ├── tsconfig.json
    └── src/plugin.ts
```

## 2. Manifest

Replace the generated `manifest.yaml` with:

```yaml
schema_version: 1
id: com.example.hello-panel
name: "Hello Panel"
version: "0.1.0"
description: "Prints the drone's battery pack voltage in a node-detail tab."
author: "Your Name"
license: "GPL-3.0-or-later"
risk: low

compatibility:
  ados_version: ">=0.10.0"
  gcs_version: ">=0.5.0"
  supported_boards: ["*"]

gcs:
  entrypoint: "gcs/plugin.bundle.js"
  isolation: iframe
  permissions:
    - id: ui.slot.node-detail-tab
    - id: telemetry.subscribe.battery
  contributes:
    tabs:
      - id: hello-tab
        slot: node.detail.tab
        profile: ["drone"]
        title: "Hello"
        icon: "battery"
        order: 90
  locales:
    - en
```

What each part does:

- **No `agent` block.** A manifest needs at least one half; this one
  ships only the GCS half, so nothing installs on the drone.
- **`tabs`** mounts the bundle as a tab on the node-detail panel. A tab
  always lives in the `node.detail.tab` slot. `profile: ["drone"]`
  offers it on drones only; leave `profile` out to offer it on every
  node profile.
- **`ui.slot.node-detail-tab`** is the permission that lets the tab
  mount. Every visual contribution needs its matching `ui.slot.*`
  permission, or the host drops it.
- **`telemetry.subscribe.battery`** is the topic-scoped telemetry grant.
  The host checks it on every `telemetry.subscribe` call for the
  `battery` topic, so a plugin cannot read a topic it did not declare.
- **`risk: low`**: the plugin reads telemetry and draws a tab. It
  sends no commands, opens no network connections and touches no files.

See [contribution points](/developers/contribution-points) for every
contribution kind and [permissions](/developers/permissions) for the
full capability list.

## 3. The panel

Keep the logic in its own module so it can be tested without a browser.
Create `gcs/src/panel.ts`:

```ts
import type { BatterySample, PluginContext } from "@altnautica/plugin-sdk";

export function formatPack(sample: BatterySample): string {
  return `Pack ${sample.packId}: ${sample.totalVoltageV.toFixed(2)} V`;
}

export async function mountPanel(
  ctx: PluginContext,
  el: HTMLElement,
): Promise<() => void> {
  el.textContent = "Waiting for battery telemetry";
  return ctx.telemetry.subscribe<BatterySample>("battery", (sample) => {
    el.textContent = formatPack(sample);
  });
}
```

`ctx.telemetry.subscribe` asks the host to open the `battery` stream
for the drone the tab is mounted on. It resolves once the host accepts
the subscription, and the value it resolves with is an unsubscribe
function. If the grant is missing, the promise rejects and no handler
is left behind.

Every frame on the `battery` topic is a `BatterySample`:

| Field | Type | Notes |
|---|---|---|
| `timestampMs` | number | Sample time in milliseconds. |
| `packId` | number | Battery instance reported by the flight controller. |
| `cellVoltagesV` | number[] | Empty when the flight controller does not report cells. |
| `totalVoltageV` | number | Pack voltage. |
| `currentA` | number or null | |
| `consumedAh` | number or null | |
| `remainingPercent` | number or null | |
| `temperatureC` | number or null | |
| `cellCount` | number or null | |

Values the flight controller does not report arrive as `null`.

## 4. The entry point

Replace `gcs/src/plugin.ts` with:

```ts
import { definePlugin } from "@altnautica/plugin-sdk";
import { mountPanel } from "./panel";

let stop: (() => void) | null = null;

definePlugin({
  id: "com.example.hello-panel",
  version: "0.1.0",
  async mount(ctx) {
    const el = document.createElement("div");
    el.style.font = "14px system-ui, sans-serif";
    el.style.padding = "12px";
    document.body.appendChild(el);
    stop = await mountPanel(ctx, el);
  },
  unmount() {
    stop?.();
    stop = null;
  },
});
```

`definePlugin` is the only call a plugin module must make. The host
loads the bundle inside the tab's iframe, and the SDK calls `mount` with
a `PluginContext` wired to the host bridge. `unmount` runs when the tab
closes or the operator switches node, and releases the telemetry
stream.

## 5. Test without a host

The SDK ships a synthetic host harness at
`@altnautica/plugin-sdk/harness`. It runs the plugin against an
in-memory transport, applies the same capability gate as the real host,
and lets you push telemetry frames by hand. Create
`gcs/src/panel.test.ts`:

```ts
import { describe, expect, it } from "vitest";
import { createPluginHarness } from "@altnautica/plugin-sdk/harness";
import { mountPanel } from "./panel";

describe("hello panel", () => {
  it("prints the pack voltage", async () => {
    const el = { textContent: "" } as HTMLElement;
    const harness = createPluginHarness({
      grantedCapabilities: ["telemetry.subscribe.battery"],
      mount: async (ctx) => {
        await mountPanel(ctx, el);
      },
    });
    await harness.start();

    harness.pushTelemetry("battery", {
      timestampMs: 0,
      packId: 0,
      cellVoltagesV: [4.1, 4.1, 4.1, 4.12],
      totalVoltageV: 16.42,
      currentA: null,
      consumedAh: null,
      remainingPercent: null,
      temperatureC: null,
      cellCount: 4,
    });

    expect(el.textContent).toBe("Pack 0: 16.42 V");
    await harness.teardown();
  });
});
```

Run it from the GCS package:

```sh
cd extensions/hello-panel/gcs
pnpm test
```

`harness.calls` records every request the plugin made, including the
capability it claimed, so you can also assert that the plugin asked for
`telemetry.subscribe.battery` and nothing more.

## 6. Pack and sign

From the monorepo root:

```sh
scripts/pack.sh hello-panel
```

`pack.sh` builds the GCS bundle (esbuild into `gcs/plugin.bundle.js`),
checks that every entrypoint the manifest declares is present, and zips
the result into `extensions/hello-panel/dist/com.example.hello-panel-0.1.0.adosplug`.
The name comes from the manifest `id` and `version`.

Signing is a separate step. With your publisher Ed25519 key in
`ADOS_SIGNING_KEY` and its id in `ADOS_SIGNING_KEY_ID`:

```sh
ADOS_SIGNING_KEY=/path/to/key.priv.pem \
ADOS_SIGNING_KEY_ID=my-publisher-2026-A \
  scripts/sign.sh extensions/hello-panel/dist/com.example.hello-panel-0.1.0.adosplug
```

That writes a `*.signed.adosplug` carrying a `SIGNATURE` file: the
signer id, then the base64 Ed25519 signature over the canonical payload
hash. See [distribution and local install](/developers/distribution-local-install)
for key generation and how a node comes to trust your signer.

## 7. Install

Open the drone from the fleet, switch to its **Extensions** tab, and
choose **Install from file**. Drop in the archive, review the two
permissions, and approve. The **Hello** tab appears on the drone's
node-detail panel and updates with every battery frame.
