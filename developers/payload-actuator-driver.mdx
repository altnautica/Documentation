A `PayloadActuatorDriver` controls a non-imaging payload: a sprayer, dropper, claw, sampler, winch, or any other actuator your plugin triggers.

## The interface

```python
from ados.sdk.drivers.payload_actuator import (
    PayloadActuatorDriver,
    PayloadCandidate,
    PayloadCapabilities,
    PayloadSession,
    PayloadCommand,
    PayloadState,
)

class MyPayloadDriver(PayloadActuatorDriver):
    async def discover(self) -> list[PayloadCandidate]:
        ...

    async def open(self, candidate, config) -> PayloadSession:
        ...

    async def close(self, session) -> None:
        ...

    def capabilities(self, session) -> PayloadCapabilities:
        ...

    async def actuate(self, session, command: PayloadCommand) -> None:
        ...

    def get_state(self, session) -> PayloadState:
        ...
```

<DriverRustNote trait="PayloadActuatorDriver" methods="discover, open, close, capabilities, actuate, get_state" />

In Rust, `actuate` returns `DriverError::InvalidParam` when `command.action_id` is not in `PayloadCapabilities::actions`, and `args` and `metadata` are msgpack value maps.

## Capabilities

```python
PayloadCapabilities(
    actions=("arm", "trigger", "stop", "set_flow_rate"),
    has_position_feedback=False,
    has_flow_feedback=True,
    metadata={"max_payload_kg": 2.5, "update_hz": 10.0},
)
```

`actions` is the tuple of `action_id` strings the driver accepts in `PayloadCommand`. `metadata` holds driver-specific values (maximum payload mass, refill volume, firmware version).

## Commands

```python
PayloadCommand(
    action_id="trigger",
    args={"duration_s": 1.5, "intensity": 0.8},
)
```

`action_id` is mandatory. `args` is a free-form dict the driver validates; raise `ValueError` on unknown keys.

## State

```python
PayloadState(
    timestamp_ns=ns,
    last_action_id="trigger",
    busy=False,
    metadata={"flow_lpm": 0.0, "tank_pct": 65.0, "armed": True},
)
```

`busy=True` while an action is in flight. Your plugin calls `actuate` itself; serialise calls per session in your plugin. A driver that sees a sustained fault reports it under `metadata["error"]` and raises `DriverError` on the next `actuate` call.

## Opening the driver from your plugin

Your plugin opens the driver in `on_start` and calls `actuate` when its GCS half or a mission action asks for it. The pattern is on [Driver layer](/developers/driver-layer#running-a-driver-from-your-plugin). A GPIO-driven actuator needs `hardware.gpio_out`; a serial one needs `hardware.uart`. Risk levels are on [Permissions](/developers/permissions).

<Warning>
A payload that moves or releases mass in flight is a flight-safety action. Read [Safety](/operations/safety) before you fly it.
</Warning>
