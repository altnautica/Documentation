A `GimbalDriver` moves a stabilised mount to a commanded attitude or rate, and reports the current pointing state.

The first-party reference is `MavlinkGimbalDriver` in the MAVLink Gimbal v2 plugin ([`extensions/mavlink-gimbal-v2`](https://github.com/altnautica/ADOSExtensions/tree/main/extensions/mavlink-gimbal-v2)). It drives any gimbal that speaks the MAVLink Gimbal Manager Protocol v2 (ArduPilot or PX4 forwarding; Storm32 NT and Gremsy in MAVLink mode). It ships no serial SimpleBGC, Storm32 or Gremsy drivers.

## The interface

```python
from ados.sdk.drivers.gimbal import (
    GimbalDriver,
    GimbalCandidate,
    GimbalCapabilities,
    GimbalSession,
    GimbalState,
)

class MyGimbalDriver(GimbalDriver):
    async def discover(self) -> list[GimbalCandidate]:
        ...

    async def open(self, candidate, config) -> GimbalSession:
        ...

    async def close(self, session) -> None:
        ...

    def capabilities(self, session) -> GimbalCapabilities:
        ...

    async def command_attitude(
        self, session, pitch_deg, yaw_deg, roll_deg=0.0
    ) -> None:
        ...

    async def command_rate(
        self, session, pitch_rate_dps, yaw_rate_dps, roll_rate_dps=0.0
    ) -> None:
        ...

    def get_state(self, session) -> GimbalState:
        ...

    async def state_iterator(self, session):
        # async generator yielding GimbalState at the gimbal's update rate
        ...
```

<DriverRustNote trait="GimbalDriver" methods="discover, open, close, capabilities, command_attitude, command_rate, get_state, state_iterator" />

In Rust the angles are `f32`, and `command_rate` returns `DriverError::NotSupported` on a position-only mount.

## Capabilities

```python
GimbalCapabilities(
    has_pitch=True,
    has_yaw=True,
    has_roll=False,
    pitch_min_deg=-135.0,
    pitch_max_deg=45.0,
    yaw_min_deg=-180.0,
    yaw_max_deg=180.0,
    roll_min_deg=0.0,
    roll_max_deg=0.0,
    max_rate_dps=120.0,
    supports_follow_mode=True,
    supports_lock_mode=True,
)
```

Limits are degrees from neutral. `max_rate_dps=None` means the gimbal is position-controlled only.

## State

```python
GimbalState(
    timestamp_ns=ns,
    pitch_deg=-22.5,
    yaw_deg=10.0,
    roll_deg=0.0,
    pitch_rate_dps=0.0,
    yaw_rate_dps=0.0,
    roll_rate_dps=0.0,
    mode="follow",
    metadata=None,
)
```

Drivers that cannot report rates leave `*_rate_dps` at `0.0`. Put driver-specific status (fault codes, mount temperature, firmware version) under `metadata`. Your plugin's GCS half renders this data; publish it with `ctx.telemetry.extend` or `ctx.events.publish`.

## Region of interest

ROI is not part of the `GimbalDriver` contract. A driver that supports it adds its own methods. The reference driver adds `set_roi_location` and `clear_roi`, which map to `MAV_CMD_DO_SET_ROI_LOCATION` (195) and `MAV_CMD_DO_SET_ROI_NONE` (197).

## Opening the driver from your plugin

The reference plugin builds its driver in `on_start` around a router handle for the agent's MAVLink link, registers its MAVLink component, and feeds incoming `GIMBAL_DEVICE_ATTITUDE_STATUS` messages to `driver.on_attitude_status(...)`. See `agent/src/altnautica_gimbal_v2/plugin.py`. For MAVLink gimbals declare `mavlink.read`, `mavlink.write` and `mavlink.component.gimbal`; the full table is on [Driver layer](/developers/driver-layer#manifest-permissions).

## Testing without hardware

Construct the driver against a mock MAVLink router. The reference plugin's `agent/tests/test_mavlink_driver.py` shows the round trip: command pitch -30 and yaw 45, capture the encoded `COMMAND_LONG`, feed a `GIMBAL_DEVICE_ATTITUDE_STATUS` sample through `driver.on_attitude_status(...)`, and assert the state updates.
