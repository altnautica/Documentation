# Configuration

The agent's configuration lives at `/etc/ados/config.yaml`. It is a single YAML file validated by Pydantic models at load time. Every field has a sensible default, so a minimal config (or no config file at all) produces a working agent.

## Config search order

When the agent starts, it looks for config in this order:

1. Path passed as argument or environment variable (`ADOS_CONFIG`)
2. `/etc/ados/config.yaml`
3. `./config.yaml` (current directory)
4. Pure defaults (no file needed)

## Full config structure

The excerpt below covers the sections operators touch. The full model also
carries `radio:`, `atlas:` and `perception:`, documented with the subsystems
that read them. Keys the running schema does not recognise are preserved on
write rather than dropped, so a config from a newer or older build survives a
round trip.

```yaml
agent:
  device_id: ""           # Auto-generated on first boot
  name: "my-drone"        # Human-readable name
  tier: "auto"            # auto | 1 | 2 | 3 | 4
  profile: "auto"         # auto | drone | ground_station | workstation | compute

mavlink:
  serial_port: ""         # Autodetected if empty
  baud_rate: 57600        # Applies only when serial_port is set
  system_id: 1
  component_id: 191
  # MAVLink v2 message signing is managed from the GCS. The key lives in
  # the browser; the agent holds no key material. See /drone-agent/mavlink-signing.
  endpoints:
    - type: websocket
      host: "0.0.0.0"
      port: 8765
      enabled: true
  ws_proxy_enforce_auth: true    # Paired node refuses an unauthorized WebSocket
  raw_proxy_enforce_auth: false  # TCP 5760, UDP 14550/14551: no credential channel
  aux_uplink_enforce_origin: false  # Refuse an unidentified caller the radio uplink

video:
  mode: "auto"            # auto | wfb | cloud | disabled
  wfb:
    interface: ""          # RTL8812EU interface, auto-detected
    channel: 149           # 5 GHz channel
    tx_power: 25           # dBm
    fec_k: 8              # FEC data blocks
    fec_n: 12             # FEC total blocks (data + parity)
  camera:
    source: "csi"         # csi | usb | ip, or a device path (/dev/video0) or RTSP URL
    codec: "h264"         # h264 | h265
    width: 1280
    height: 720
    fps: 30
    bitrate_kbps: 4000
  recording:
    enabled: false
    path: "/var/ados/recordings"
    retention: "24h"      # how long segments are kept before mediamtx deletes them
  cloud_relay_url: ""

network:
  wifi_client:
    enabled: false
    ssid: ""
    password: ""
  cellular:
    enabled: false
    apn: ""
  hotspot:
    enabled: false
    ssid: "ADOS-{device_id}"
    password: ""          # empty = per-unit passphrase generated on first use, stored 0600 at /etc/ados/ap-passphrase
    channel: 6

server:
  mode: "local"           # cloud | self_hosted | local
  cloud:
    url: "https://your-convex.example.com:3211"   # Convex site origin (HTTP actions)
    mqtt_broker: "your-mqtt.example.com"
    mqtt_port: 443
  self_hosted:
    url: "https://your-convex.example.com:3211"   # Convex site origin (HTTP actions)
    mqtt_broker: "your-mqtt.example.com"
    mqtt_port: 8883
    api_key: ""
  telemetry_rate: 2       # Hz, MQTT publish rate
  heartbeat_interval: 5   # Seconds
  mqtt_transport: "websockets"  # websockets | tcp
  mqtt_username: "ados"
  mqtt_password: ""

remote_access:
  provider: "none"        # none | cloudflare
  public_urls: []
  cloudflare: {}          # Cloudflare Tunnel quick-install settings

security:
  tls:
    enabled: false
    cert_path: "/etc/ados/certs/device.crt"
    key_path: "/etc/ados/certs/device.key"
    ca_path: "/etc/ados/certs/ca.crt"
  wireguard:
    enabled: false
    config_path: "/etc/wireguard/ados.conf"
  api:
    api_key: ""
    cors_enabled: true
    cors_origins: []          # Built-in localhost defaults always apply
    cors_origins_extra: []    # Extra origins added on top of the defaults
  hmac_enabled: false
  hmac_secret: ""

api:
  rest:
    enabled: true
    host: "0.0.0.0"
    port: 8080
  mission_control_url: ""

logging:
  level: "info"           # debug | info | warning | error
  max_size_mb: 50
  keep_count: 5
  flight_log_dir: "/var/ados/logs/flights"

pairing:
  state_path: "/etc/ados/pairing.json"
  convex_url: "https://convex-site.altnautica.com"
  beacon_interval: 30
  heartbeat_interval: 60

discovery:
  mdns_enabled: true
  service_type: "_ados._tcp.local."

vision:
  enabled: false
  backend: "auto"         # auto | rknn | tensorrt | opencv_dnn | tflite
  confidence_threshold: 0.5
  models_dir: "/opt/ados/models/vision"
  models_cache_max_mb: 500

swarm:
  enabled: false
  lora:
    interface: ""
    frequency: 915000000
    bandwidth: 125000
    spreading_factor: 7
  wifi_direct:
    enabled: false
    interface: ""
  role: "auto"
  default_formation: "line"
  default_spacing: 10

ground_station:
  share_uplink: false
  paired_drone_id: null
  paired_at: null
  ui:
    oled: {}
    buttons: {}
    screens: {}

ui:
  theme: "dark"             # dark | light
```

## Key settings explained

### Agent profile

```yaml
agent:
  profile: "auto"  # auto | drone | ground_station | workstation | compute
```

When set to `auto`, the agent fingerprints the hardware at boot. If it finds an OLED on I2C, GPIO buttons, an RTL8812EU in receive mode, and no flight controller, it picks `ground_station`. Otherwise it picks `drone`.

`workstation` and `compute` are never auto-detected. They are chosen at install
time with `--profile`, and the macOS installer defaults to `workstation`.
`ados profile set` persists only `drone` and `ground_station`. See
[Node profiles](/getting-started/node-profiles).

Force a specific profile by setting it explicitly.

### Hotspot passphrase

```yaml
network:
  hotspot:
    password: ""
```

Empty is the shipped default and it means "generate a per-unit passphrase on
first use". The generated value is written mode 0600 to
`/etc/ados/ap-passphrase` and shown on the OLED access-point page, in the on-box
console, and on the installer's completion card. Read it with
`ados network ap-passphrase`.

<Warning>
A configured value takes precedence over the generated one, so naming a
passphrase here gives every unit in your fleet the same key. Set it only to pin
a deliberate shared passphrase.
</Warning>

### Device TLS

```yaml
security:
  tls:
    enabled: false
```

Device TLS ships **off**. The effective default comes from the agent's
`defaults.yaml`, not from the Pydantic class default (which reads `true` and is
overridden at load), so a code reading can mislead here. The shipped LAN posture
is plain HTTP on port 8080 with the pairing key at the auth edge. Turn TLS on
deliberately, with certificates you provide at the three `*_path` keys. See
[Hardening](/operations/hardening).

### Pairing backend URL

```yaml
pairing:
  convex_url: "https://convex-site.altnautica.com"
```

This ships populated with the hosted backend origin. A self-hosted deployment
MUST overwrite it: setting `server.mode: self_hosted` and filling
`server.self_hosted` is not enough, because the beacon and heartbeat read
`pairing.convex_url` and will keep talking to the hosted origin. See
[Self-hosting the agent](/developers/self-hosting/agent).

### MAVLink serial port

```yaml
mavlink:
  serial_port: ""
  baud_rate: 57600
```

Leave `serial_port` empty for autodetection. The agent scans `/dev/ttyACM*`, `/dev/ttyAMA*`, `/dev/ttyUSB*`, and `/dev/ttyS*`, plus any USB serial device regardless of its node name.

`baud_rate` applies only when `serial_port` also names a port. With the port empty, the configured baud is skipped entirely and the agent sweeps `115200, 921600, 57600, 230400, 1500000, 38400, 19200`, listening 1.5 seconds at each for a heartbeat. A default-config drone therefore usually runs at 115200 even though the file says 57600.

To pin a rate, set both keys:

```yaml
mavlink:
  serial_port: "/dev/ttyS0"
  baud_rate: 921600
```

Check what the link settled on with `ados status`, not by reading the config file. See [MAVLink Proxy](/drone-agent/mavlink-proxy#what-baud-your-drone-is-actually-running).

### Video codec

```yaml
video:
  camera:
    codec: "h264"
    bitrate_kbps: 4000
```

Use `h264` for maximum compatibility. Browser-based players (MSE, WebRTC) expect `avc1.640029` (H.264 High Profile Level 4.1). H.265 saves bandwidth but browser support is inconsistent for WebRTC.

### Cloud server mode

```yaml
server:
  mode: "local"  # cloud | self_hosted | local
```

- **cloud**: connects to the ADOS cloud backend.
- **self_hosted**: connects to your own MQTT broker and Convex instance.
- **local**: no cloud connectivity; Mission Control reaches the agent over the LAN. Default.

<Warning>
For both `cloud` and `self_hosted` modes, the `url` must point at the Convex **site** origin on port `:3211` (HTTP actions: pairing register, heartbeat, command poll), not the client API on `:3210`. If you paste the `:3210` URL, the register call lands on the wrong origin and returns a 404. The agent normalizes a known `:3210` URL to `:3211` as a safety net, but set `:3211` explicitly. See [Self-hosting the agent](/developers/self-hosting/agent).
</Warning>

### Vision backend

```yaml
vision:
  enabled: false
  backend: "auto"
```

When `auto`, the agent probes for available inference backends in order: RKNN (Rockchip NPU), TensorRT (NVIDIA), OpenCV DNN, TFLite. It picks the first one that initializes successfully.

## Reading and writing config

Use the setup webapp for common MAVLink, video, network, and remote-access
settings. Advanced users can edit `/etc/ados/config.yaml` directly or use the
REST API.

### From the REST API

```bash
# Read config
curl http://localhost:8080/api/config \
  -H "X-ADOS-Key: your_key"

# Write a value. The body is one dot-separated key path plus its value;
# a native JSON scalar (true, 25) and a string ("25") are both accepted.
curl -X PUT http://localhost:8080/api/config \
  -H "X-ADOS-Key: your_key" \
  -H "Content-Type: application/json" \
  -d '{"key": "video.camera.fps", "value": 25}'
```

The response carries `persisted`. A write that mutated the running model but
could not reach `/etc/ados/config.yaml` answers `"persisted": false` with a
`persist_error` string naming the reason, so a change that will not survive a
restart is visible instead of silently reported as saved:

```json
{ "status": "ok", "key": "video.camera.fps", "value": 25, "persisted": true }
```

Reading a secret path returns `***`. Writing that sentinel back is rejected with
a 400, so a read-display-edit-write round trip cannot overwrite a real secret
with the placeholder.

`GET /api/config/schema` returns the build-time-embedded shape of the whole
config surface. Build a settings UI against that rather than against a
hand-written form.

### Editing the file

You can edit `/etc/ados/config.yaml` directly with any text editor, then restart the affected service (see the tip at the end of this page). The terminal status page (`ados`) is read-only and does not edit config.

## Per-board overrides

The install script writes board-specific overrides into `/etc/ados/config.yaml` during installation. For example, a Raspberry Pi 4B gets:

```yaml
mavlink:
  serial_port: "/dev/ttyAMA0"
```

While a Radxa ROCK 5C Lite gets:

```yaml
mavlink:
  serial_port: "/dev/ttyS0"
  baud_rate: 921600
```

These overrides are merged on top of the built-in defaults. Your manual edits always take priority.

<Tip>
After editing the config file manually, restart the affected service for changes to take effect. For example, `sudo systemctl restart ados-mavlink` after changing the baud rate.
</Tip>
