# Vision Navigation

Vision Navigation lets a drone hold position and fly missions when GPS is unreliable: indoors, under bridges, under canopy, in urban canyons. The companion computer tracks the ground under a downward camera, turns that into an angular flow rate, and sends it to the flight controller as MAVLink `OPTICAL_FLOW_RAD` at the camera frame rate (around 30 Hz). The flight controller's EKF fuses it, so `LOITER`, position hold, and missions keep working unchanged.

<Note>
Vision Navigation is a first-party extension, `com.altnautica.vision-nav` (version 0.4.1). It ships from the public [ADOSExtensions](https://github.com/altnautica/ADOSExtensions/tree/main/extensions/vision-nav) repository under GPL-3.0-or-later. You install it per drone from the drone's **Extensions** tab. See [Install on a drone](/drone-agent/vision-nav-install).
</Note>

## Three modes

The per-drone `mode` setting picks one of three estimators:

| Mode | Hardware | What you get |
|---|---|---|
| `off` | none | The plugin stays loaded and reports health. Nothing is sent to the flight controller. |
| `optical_flow` | downward camera plus a rangefinder | The default GPS-denied path. Low-altitude hover and waypoint flight over textured ground. |
| `optical_flow_degraded` | downward camera only | Same tracker. Scale comes from the barometer (or GPS height outdoors) instead of a rangefinder. Looser, and it drifts above about 5 m. |

Visual-inertial odometry (VIO) and the two-camera hybrid mode are not part of the current release. See [Modes](/drone-agent/vision-nav-modes) for the per-mode detail and the pre-arm checks.

## What you can do with it

### GPS-denied hover

**Mode:** `optical_flow`. **Hardware:** downward camera plus rangefinder.

The drone holds position in `LOITER` (ArduPilot), `POSITION` (PX4), or NAV POSHOLD (iNav) with no GPS. The EKF integrates the flow velocity and the rangefinder height. How tight the hold is depends on the ground's texture (more corners, tighter tracking) and the rangefinder's accuracy. Indoors, under solid canopy, or anywhere a GPS receiver loses lock, the drone behaves as if it had GPS as long as the camera sees ground.

### Hover without a rangefinder

**Mode:** `optical_flow_degraded`. **Hardware:** downward camera.

Same hover behaviour with looser bounds. The plugin takes height from the flight controller's barometer and multiplies the flow quality by a per-source factor, so the EKF trusts it less. Use it where a rangefinder is impractical (very small frames, weight limits). It is the GPS-denied path of last resort, not a replacement for a rangefinder.

### Indoor waypoint flight

**Mode:** `optical_flow`. **Hardware:** downward camera plus rangefinder.

The flight controller's waypoint navigator consumes the EKF's local position the same way it consumes a GPS position; it does not care where the position came from. `AUTO` (ArduPilot) and mission mode (PX4) run indoors with waypoint accuracy bounded by the EKF's position accuracy. Warehouse runs, indoor inspection, and indoor search fit here.

### Gentler landings

**Mode:** `optical_flow`. **Hardware:** downward camera plus rangefinder.

With the rangefinder feeding height, the EKF altitude near the ground is height above the actual surface rather than above a barometric reference. Landing controllers use that directly, which helps on rough fields and raised pads.

## Supported firmware

| Firmware | Optical flow | Notes |
|---|---|---|
| ArduPilot 4.5+ (Copter, Plane, Rover) | Yes | `FLOW_TYPE = 5` |
| PX4 1.14+ | Yes | `EKF2_OF_CTRL` enabled |
| iNav 7.0+ | Yes | `opflow_hardware = MAVLINK` on a MAVLink UART |
| Betaflight | No | No position estimator to fuse flow into |

The plugin sends the same `OPTICAL_FLOW_RAD` message to all three supported firmwares. The Vision Nav tab shows the parameter reference for the drone's firmware. See [Configure optical flow](/drone-agent/vision-nav-optical-flow) for every parameter.

### Why Betaflight is not supported

Betaflight is built for racing and freestyle, not autonomous position hold. It has no position estimator, so a flow measurement has nothing inside the flight controller to feed. That is a firmware design choice the companion cannot work around. Most STM32F405, F722, and H743 boards also run iNav and ArduPilot Copter; flash one of those for GPS-denied flight.

## Supported boards

The manifest's `compatibility.supported_boards` list names these companion boards:

| Board | Manifest id |
|---|---|
| Raspberry Pi 5 (BCM2712) | `rpi5` |
| Raspberry Pi CM5 (BCM2712) | `cm5` |
| Raspberry Pi CM4 (BCM2711) | `cm4` |
| Raspberry Pi Zero 2 W | `pi-zero-2w` |
| Radxa ROCK 5C Lite (RK3582) | `rk3582` |
| Radxa CM4 (RK3588S2) | `rk3588s2` |
| Rockchip RK3576 | `rk3576` |

The agent's plugin supervisor refuses the install when the drone's HAL board id is not in that list, or when the agent is older than 0.99.125. The plugin runs with a ceiling of 512 MB RAM, 80 percent of one CPU core, and 24 processes. See [Hardware](/drone-agent/vision-nav-hardware) for camera and rangefinder picks.

## How it sits in the stack

```text
flight controller (UART)            USB / CSI camera
        |                                  |
   MAVLink router                    agent vision host
   (RAW_IMU, DISTANCE_SENSOR,              |
    GLOBAL_POSITION_INT, VFR_HUD)    shared vision frame bus
        \                                  /
         \                                /
          plugin host (agent supervisor)
                        |
          vision-nav (Rust binary) --> TF-Luna over UART (optional)
                        |
          OPTICAL_FLOW_RAD + DISTANCE_SENSOR on MAVLink component 198
```

The agent's vision host owns the camera; the plugin reads frames from the shared vision bus instead of opening a device. The plugin registers MAVLink component 198, reads the flight controller's IMU and altitude messages through the router, and publishes a `navigation` block on the agent heartbeat once a second. Mission Control renders that block in the drone's **Vision Nav** tab. See [How it works](/drone-agent/vision-nav-how-it-works) for the full path.
