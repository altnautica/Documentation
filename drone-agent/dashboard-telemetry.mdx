Telemetry is a drone-profile page at `/telemetry`. It has two tabs. **Parameters** (the default) edits the FC parameters. **Sensors** shows live attitude, battery, GPS, mode and armed state.

For Betaflight and iNav the browser reads the FC directly over the transparent MSP proxy on port `8765`; the agent forwards MSP bytes and decodes none. ArduPilot and PX4 use the agent's parameter cache and `GET /api/telemetry`.

## Parameters

<Frame caption="Parameters tab with the cache loaded and the vehicle disarmed.">
  ![Agent dashboard Telemetry Parameters tab with the category list and the parameter table](/images/drone-agent/dashboard/telemetry-parameters.png)
</Frame>

The table is virtualized for full ArduPilot tables (well over a thousand parameters). Filter by the category list or search by name. Enum labels, ranges and units come from bundled metadata.

<Warning>
Parameter writes are refused while the vehicle is armed or before the FC has reported its armed state. The **Save** button stays disabled, and the agent also answers `409 E_ARMED`. See [Safety interlocks](/drone-agent/dashboard-overview#safety-interlocks) and [Safety](/operations/safety).
</Warning>

<Steps>
  <Step title="Find the parameter">
    Type in **Search by name** (a case-insensitive match on the name only), or pick a category.
  </Step>
  <Step title="Edit">
    Use the number field, the enum dropdown, or **Set bits…** for bitmasks. Edited rows highlight; **Modified only** filters the table to your drafts.
  </Step>
  <Step title="Save">
    Press **Save N**, then **Save all** in the **Save N parameters?** confirm. The agent writes each parameter and waits for its PARAM_VALUE echo, up to 2 s per parameter. ArduPilot and PX4 store a parameter on write; there is no separate flash step.
  </Step>
  <Step title="Discard">
    **Discard** drops every draft.
  </Step>
</Steps>

## Sensors

<Frame caption="Sensors tab on an ArduPilot drone.">
  ![Agent dashboard Telemetry Sensors tab showing attitude, battery, GPS, mode and armed state](/images/drone-agent/dashboard/telemetry-sensors.png)
</Frame>

The MAVLink view polls `GET /api/telemetry` once a second:

| Group | Fields |
| --- | --- |
| Attitude | roll, pitch, yaw |
| Battery | voltage, current, remaining |
| GPS | fix type, sats, hdop, position, alt (rel) |
| State | mode, armed |

## Data sources

| Endpoint | Used for |
| --- | --- |
| `GET /api/params` | the parameter cache |
| `POST /api/params/{name}` | one write per edited parameter |
| `GET /api/telemetry` | Sensors (ArduPilot, PX4), 1 s |
| `GET /api/status` | FC firmware family, to pick MAVLink or MSP |
| `ws://<host>:8765` | MSP proxy (Betaflight, iNav) |

## Troubleshooting

<AccordionGroup>
  <Accordion title="The table stays empty">
    The page shows its loading state while it waits:

    - **loading parameters…**: the first fetch is in flight.
    - **Priming parameter cache from FC… X of Y parameters received.**: the FC is streaming its table; wait.
    - **Couldn't reach the flight controller.**: the agent could not send PARAM_REQUEST_LIST, or the FC did not answer within 30 seconds. Check the FC serial cable, baud rate and power.
    - **No parameters cached yet.**: the cache is empty. Check the MAV tile on Home.
  </Accordion>
  <Accordion title="Save reports failed or pending parameters">
    Each failure shows a toast `<NAME>: failed`, then a summary "Saved X, Y failed, Z pending FC ack." A pending parameter was sent but the FC had not echoed PARAM_VALUE within 2 s; it may still apply under heavy load. Reload the table to confirm.
  </Accordion>
  <Accordion title="Save stays disabled">
    The vehicle is armed, or the FC has not reported its armed state yet. Disarm, and check the Flight Controller panel on Home.
  </Accordion>
</AccordionGroup>
