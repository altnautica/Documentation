# Vision Navigation modes

The plugin runs one of three estimator modes, set by the per-drone `mode` key in its configuration. The Vision Nav tab's mode card is read-only: it lists the modes the agent advertises in `availableEstimators` and marks the active one. Changing `mode` restarts the plugin with the new estimator.

## Quick decision

| If you have... | Use... |
|---|---|
| Downward camera plus rangefinder | `optical_flow` |
| Downward camera only | `optical_flow_degraded` |
| Neither, or you're checking hardware | `off` |

## Side by side

| | `off` | `optical_flow` | `optical_flow_degraded` |
|---|---|---|---|
| Estimator | none | Lucas-Kanade | Lucas-Kanade |
| Camera | not used | downward | downward |
| Rangefinder | not used | required | not used |
| IMU | not used | gyro, for derotation | gyro, for derotation |
| Scale source | none | rangefinder | barometer, GPS height, or a fixed 1.5 m |
| Output | nothing | `OPTICAL_FLOW_RAD` on component 198 | `OPTICAL_FLOW_RAD` on component 198 |
| Rate | none | camera frame rate (around 30 Hz) | camera frame rate (around 30 Hz) |
| Pre-arm checks | none | companion, flow quality, rangefinder | companion, flow quality, scale source |
| Accuracy | n/a | best | lower, drifts above about 5 m |

The firmware side is the same for both flow modes: ArduPilot `FLOW_TYPE = 5` with `EK3_SRC1_VELXY = 5`, PX4 `EKF2_OF_CTRL` enabled, iNav `opflow_hardware = MAVLINK`. See [Configure optical flow](/drone-agent/vision-nav-optical-flow).

**Rangefinder or not.** A rangefinder gives the lowest drift and the full flow quality. Without one you can still fly GPS-denied, but the plugin scales the quality down by at least 30 percent so the EKF trusts the samples less. The rangefinder is cheap insurance.

<Note>
The current release offers only these three modes. Visual-inertial odometry and the two-camera hybrid mode are not available; a stored configuration that names one of them is rejected and leaves vision navigation disengaged.
</Note>

## off

The plugin is loaded, subscribes to its inputs, and publishes the heartbeat, but the estimator emits nothing. The pre-arm report is empty and always armable. Useful for:

- Checking that the camera, IMU, and rangefinder show up before you fly.
- Leaving the plugin installed on a drone that flies on GPS today.

Disengaging with the **Engage** Skill also runs the plugin as `off` without changing the configured `mode`.

## optical_flow

The default GPS-denied path. The Lucas-Kanade tracker turns two consecutive downward frames into an angular flow rate, the gyro removes the part caused by the drone rotating, and the rangefinder gives the height. The result is `OPTICAL_FLOW_RAD` on component 198 at the camera frame rate. When the rangefinder is wired to the companion, the plugin also sends its reading as `DISTANCE_SENSOR` on the same component.

Use this mode when:

- You have a downward USB or CSI camera.
- You have a rangefinder, either relayed by the flight controller or a TF-Luna on a companion UART.
- You want the most accurate estimator the plugin offers for low-altitude hover and waypoint flight.

The estimator starts in `init`, moves to `converged` on the first sample at or above the quality gate (50 out of 255), and reports `degraded` when a later sample drops below it.

## optical_flow_degraded

The same tracker, with height taken from a four-rung ladder instead of a rangefinder. On every frame the plugin picks the first healthy rung:

| Rung | Source | Healthy when | Quality multiplier |
|---|---|---|---|
| 1 | `GLOBAL_POSITION_INT.relative_alt` (the FC's baro-fused height) | received in the last 2 s | 0.7 |
| 2 | `VFR_HUD.alt` minus the first value seen (take-off height) | received in the last 2 s | 0.6 |
| 3 | `GPS_RAW_INT.alt` minus take-off height | outdoor flag on, 3D fix, `eph` at most 200 cm, received in the last 2 s | 0.4 |
| 4 | fixed 1.5 m | always | 0.2 |

The chosen height is clamped to 0.3 to 50 m so a glitch cannot produce a runaway scale. The multiplier is applied to the tracker's raw quality before the message goes out, so the EKF de-weights the weaker rungs on its own. A raw quality of at least 72 is needed for the scaled value to clear the gate of 50 on the best rung.

<Note>
The GPS rung is gated on an outdoor flag that the current release leaves off, so in practice the ladder steps from the barometer rungs straight to the 1.5 m fallback.
</Note>

The estimator reports `degraded` whenever it is on the fixed 1.5 m rung, regardless of flow quality. The heartbeat labels that rung's scale source as `baro`.

Use this mode when:

- The airframe has no rangefinder.
- The flight is short and low, where the barometer is trustworthy.
- You accept lower horizontal velocity accuracy than the rangefinder mode.

## Pre-arm checks

The plugin's pre-arm gate runs every frame and publishes its report on the heartbeat. Each check is `ok`, `pending`, or `blocking` with a short reason; the drone is armable in this mode only when every check is `ok`.

| Check id | Card label | `off` | `optical_flow` | `optical_flow_degraded` |
|---|---|---|---|---|
| `companion_active` | Companion process active | | required | required |
| `flow_quality` | Optical flow quality | | required | required |
| `rangefinder` | Rangefinder healthy | | required | |
| `scale_source` | Altitude scale source | | | required |

What each check looks at:

- **`companion_active`**: `pending` until the companion reports active (the first converged sample), `blocking` once it has gone critical.
- **`flow_quality`**: `pending` until the first flow sample, then `ok` at or above 50 out of 255.
- **`rangefinder`**: `ok` when `rangefinder.topology` is `companion` or `fc`. It checks that a rangefinder is configured, not that it is currently reading; watch the distance on the sensors card.
- **`scale_source`**: `ok` when the sample carries a scale source.

These checks are the plugin's own. The flight controller still runs its own arming checks on top.

## Within-mode degradation

The plugin never switches modes in flight. Mode is an operator decision. Inside a mode it degrades in the open:

1. **`optical_flow`**: when flow quality drops below the gate after converging, the estimator reports `degraded`. If the rangefinder stops reading, samples go out without a distance.
2. **`optical_flow_degraded`**: the scale ladder walks itself every frame. On the fixed rung the estimator reports `degraded`.
3. **Both**: a `degraded` or `failed` streak of 2 seconds flips the companion to critical, which shows on the Vision Nav tab and in the companion's MAVLink `HEARTBEAT` as `MAV_STATE_CRITICAL`.

Your escape hatch is the flight controller: switch its EKF source set back to GPS (ArduPilot's RC source-set switch), change flight mode, or land. See [How it works](/drone-agent/vision-nav-how-it-works#fallback-and-recovery).
