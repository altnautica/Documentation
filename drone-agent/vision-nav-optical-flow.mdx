# Configure optical flow

This page covers the per-drone configuration once the plugin is installed and enabled. The order matters: set the plugin's keys, set the flight controller's parameters, then check pre-arm.

## Plugin configuration

Open the drone's **Extensions** tab and open the plugin's per-drone configuration. The keys come from `config-schema.json`.

### Mode

| Key | Values | Default |
|---|---|---|
| `mode` | `off`, `optical_flow`, `optical_flow_degraded` | `off` |

See [Modes](/drone-agent/vision-nav-modes). The **Engage** Skill writes a separate `active` flag; when it is `false`, the plugin runs as `off` whatever `mode` says.

### Camera

The agent's vision host owns the camera and sets the capture resolution and rate. The plugin subscribes to the vision host's frame stream; these keys describe the camera rather than open it.

| Key | Values | Notes |
|---|---|---|
| `camera.device_path` | `/dev/videoN` (default `/dev/video0`) | Shown on the sensors card. |
| `camera.bus_type` | `uvc` or `csi` (default `uvc`) | |
| `camera.orientation` | `downward`, `forward`, `side`, `auto` (default `auto`) | Optical-flow modes reject `forward` and `side`. `auto` is safe only when the board profile declares the camera's role. |
| `camera.width`, `camera.height`, `camera.fps` | defaults 640, 480, 30 | Descriptive; the vision host's settings are what the plugin receives. |

### Rangefinder

| Key | Values | Notes |
|---|---|---|
| `rangefinder.topology` | `fc`, `companion`, `none` | Required. Where the rangefinder is wired. |
| `rangefinder.driver` | `fc_relay`, `tfluna_uart`, `garmin_lidarlite_i2c`, `vl53l1x_i2c` | Used only when topology is `companion`. |
| `rangefinder.device` | `/dev/ttyUSB0`, `/dev/ttyAMA0`, ... for UART; `1` or `/dev/i2c-1` for I2C | TF-Luna defaults to `/dev/ttyUSB0`. |
| `rangefinder.baud` | 1200 to 1000000 (default 115200) | UART drivers only. |

| Driver | Status |
|---|---|
| `fc_relay` (topology `fc`) | Implemented. The flight controller reads the rangefinder and streams `DISTANCE_SENSOR`; the plugin uses the latest reading if it is under 200 ms old. Works for any sensor the flight controller supports. |
| `tfluna_uart` | Implemented. Benewake TF-Luna on a companion UART. The plugin also forwards its readings to the flight controller as `DISTANCE_SENSOR` on component 198. |
| `garmin_lidarlite_i2c`, `vl53l1x_i2c` | Not available yet: they return no reading until the plugin SDK exposes I2C. Wire these sensors to the flight controller and use topology `fc`. |

A healthy reading on the sensors card is non-zero, updates steadily, and matches your eyeball estimate of the distance to the ground.

### Firmware and origin

| Key | Values | Notes |
|---|---|---|
| `firmware.type` | `ardupilot`, `px4`, `inav` (default `ardupilot`) | Required. `betaflight` is not accepted. The plugin sends the same `OPTICAL_FLOW_RAD` stream to all three. |
| `firmware.ekf_source_set_index` | 1 to 3 | Records which ArduPilot `EK3_SRCn` set holds your flow source. The plugin does not switch source sets. |
| `pre_arm.auto_set_origin`, `origin_lat`, `origin_lon`, `origin_alt_m` | | Accepted by the schema. The current agent does not send an origin; set it from your ground station (see [Before you arm](#before-you-arm)). |

A configuration that fails validation (an unknown mode, or an optical-flow mode with a `forward` camera) leaves vision navigation disengaged until you fix it. The agent also reads an optional `flow_quality_min` key (0 to 255, default 50) for its own pre-arm gate; it is not in the configuration form.

## ArduPilot parameters

ArduPilot fuses optical flow in EKF3. Set these from Mission Control's parameter editor; the Vision Nav tab lists the relevant ones as a reference.

| Parameter | Set to | Why |
|---|---|---|
| `FLOW_TYPE` | `5` | MAVLink flow: accept the `OPTICAL_FLOW_RAD` the plugin sends. |
| `FLOW_ORIENT_YAW` | camera yaw offset, centidegrees | `0` when the camera's top edge faces the front of the airframe. |
| `FLOW_FXSCALER`, `FLOW_FYSCALER` | `0` | Per-axis scale trim. Leave at 0 unless you're calibrating flow scale. |
| `FLOW_HEIGHT_MIN`, `FLOW_HEIGHT_MAX` | your working range, m | Height band in which EKF3 fuses flow. |
| `EK3_SRC1_VELXY` | `5` | Horizontal velocity from optical flow (in the source set you use for flow). |
| `EK3_SRC1_POSXY` | `0` | No horizontal position source; position comes from integrated velocity. |
| `EK3_SRC1_POSZ` | `1` (baro) or `2` (rangefinder) | Vertical position. |
| `EK3_SRC1_YAW` | `1` | Compass. Flow doesn't measure yaw. |
| `EK3_SRC_OPTIONS` | per your setup | Source-set behaviour options. |
| `EK3_FLOW_DELAY` | start at `10` | Flow measurement delay in ms. Raise in 5 ms steps if the drone oscillates in `LOITER`. |
| `EK3_FLOW_QUAL_MIN` | `50` | Minimum flow quality (0 to 255) the EKF fuses. Matches the plugin's own gate. |
| `RNGFND1_TYPE` | per sensor | `10` for a MAVLink rangefinder (the TF-Luna the plugin forwards), or the sensor's own type when wired to the flight controller. |
| `RNGFND1_ORIENT` | `25` | Pointing down. |
| `ARMING_CHECK` | leave default | Keep arming checks on. |

### EKF source sets

ArduPilot has three EKF3 source sets (`EK3_SRC1_*`, `EK3_SRC2_*`, `EK3_SRC3_*`). A common layout puts GPS in set 1 and optical flow in set 2, with an RC switch set to the flight controller's EKF source-set option so you can change sets in flight. Switching back to GPS at altitude is the standard recovery when vision degrades. The plugin does not send source-set commands; the switch is yours.

## PX4 parameters

| Parameter | Set to | Why |
|---|---|---|
| `EKF2_OF_CTRL` | enabled | Fuse optical flow. |
| `EKF2_OF_DELAY` | 5 to 30 ms | Sensor-to-EKF delay. |
| `EKF2_OF_QMIN` | your threshold | Minimum flow quality for fusion. |
| `EKF2_OF_POS_X`, `_Y`, `_Z` | camera offset from the IMU, m | Lever arm (X forward, Y right, Z down). |
| `EKF2_HGT_REF` | rangefinder or baro | Primary height source. |
| `EKF2_AID_MASK` | per firmware version | Aiding sources on PX4 versions that still use the mask. |
| `SENS_FLOW_MAXR` | sensor limit, rad/s | Maximum trusted angular flow rate. |
| `SENS_FLOW_MINHGT`, `SENS_FLOW_MAXHGT` | rangefinder range, m | Height band for trusting flow. |

PX4 has no runtime source-set switch: a source change is a parameter write and an EKF restart (reboot after changing `EKF2_OF_CTRL`).

## iNav parameters

iNav 7.0 and newer consumes the same `OPTICAL_FLOW_RAD` over a MAVLink receive port.

| Parameter | Set to | Why |
|---|---|---|
| `opflow_hardware` | `MAVLINK` | Read flow from the MAVLink UART. |
| `opflow_scale` | leave default | |
| `nav_use_optflow_for_poshold` | `ON` | Flow-based position hold when GPS is unavailable. |
| `nav_extra_arming_safety` | per your setup | Extra navigation arming checks. |
| `rangefinder_hardware` | your FC-wired sensor, or `MSP` | Height reference for metric flow. |
| `nav_rangefinder_for_terrain` | `ON` | Terrain following on top of flow position hold. |

In iNav's Ports tab, enable MAVLink on the UART wired to the companion and reboot the flight controller. iNav's position hold runs from optical flow directly and doesn't need a global EKF origin.

## Betaflight

Betaflight has no position estimator, so a flow measurement has nothing to feed. The configuration rejects it, and the Vision Nav tab explains why on a Betaflight drone. Flash iNav or ArduPilot Copter on the same board; most STM32F405, F722, and H743 boards run all three.

## Before you arm

The plugin's pre-arm card covers its side: companion active, flow quality at or above 50, and a rangefinder (`optical_flow`) or a scale source (`optical_flow_degraded`). See [Modes](/drone-agent/vision-nav-modes#pre-arm-checks). The flight controller adds its own:

- **EKF origin.** Without GPS, ArduPilot has no origin for its local frame and reports `AHRS waiting for home` (or refuses position modes). Set the EKF origin from your ground station before arming.
- **EKF using flow.** The active source set must have `VELXY = 5`, and the EKF must report a healthy position before `LOITER` or a mission will arm.
- **Everything else.** Battery, compass, and the rest of the normal arming checks still apply.

## Tuning tips

- **Quality threshold.** Lower `EK3_FLOW_QUAL_MIN` toward 30 only for feature-poor floors in a safe test area. Below about 20 the tracker reports noise, not motion.
- **Delay.** If the drone oscillates in `LOITER`, the EKF is fusing flow with the wrong delay. Raise `EK3_FLOW_DELAY` in 5 ms steps until it settles.
- **Yaw.** Flow doesn't measure yaw, so compass calibration matters more than usual. Recalibrate if the drone slowly walks off in `LOITER`.
- **First hop.** Take off to 1.5 to 3 m. Below 1 m many rangefinders are near their floor; much higher and a typical lens sees fewer trackable features.
