# Installation

The agent installs with a single command. It detects your board, installs dependencies, configures systemd services, and starts everything automatically.

<Note>
Mission Control's Flash Tool surfaces this install command automatically. See [Install paths](/getting-started/install-paths) for the recommended flow per board class.
</Note>

## Quick install

SSH into your companion computer and run:

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh | sudo bash
```

That is it. The script handles everything from there.

<Note>
The install script requires root access. It installs to `/opt/ados/`, creates config at `/etc/ados/`, registers systemd services, and fetches the prebuilt Rust service binaries to `/opt/ados/bin/`. systemd is the supported process manager.
</Note>

## What the install script does

<Steps>
  <Step title="Detect the board">
    Reads `/proc/device-tree/model` and matches against the built-in board profiles (one YAML per supported SBC). Sets the tier and enables the right features for your hardware. There is no `--board` flag; detection is the only path.
  </Step>

  <Step title="Install system packages">
    Installs Python 3.11+, pip, virtualenv, and any board-specific packages (like the RTL8812EU DKMS driver for WFB-ng). Uses `apt` on Debian/Ubuntu systems.
  </Step>

  <Step title="Create the virtual environment">
    Sets up a Python venv at `/opt/ados/venv/` for the Python-backed services, and fetches the prebuilt Rust service binaries (supervisor, MAVLink router, control front, cloud relay, video, logging store, and the rest) into `/opt/ados/bin/`.
  </Step>

  <Step title="Generate device identity">
    Creates a unique device ID at `/etc/ados/device-id` using a chained fallback: Python uuid, OpenSSL random, or hostname-timestamp-pid. This ID is used for cloud pairing and mDNS.
  </Step>

  <Step title="Write default config">
    Creates `/etc/ados/config.yaml` with defaults tuned for your detected board. Serial port, baud rate, video resolution, and tier are all pre-filled.
  </Step>

  <Step title="Install systemd services">
    Copies service unit files to `/etc/systemd/system/` and enables them. The supervisor service starts at boot and manages all child services.
  </Step>

  <Step title="Start the agent">
    Runs `systemctl start ados-supervisor` which brings up the full service tree: MAVLink proxy, REST API, video pipeline (if a camera is detected), cloud relay, health monitor, and everything else your tier supports.
  </Step>
</Steps>

## Install with pairing

If you have a pairing code from ADOS Mission Control, include it during install:

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh | sudo bash -s -- --pair YOUR_CODE
```

This pairs the agent to your cloud account during installation. The drone will appear in your Mission Control dashboard as soon as it connects.

## Upgrade an existing installation

To upgrade to the latest version without losing your config:

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh | sudo bash -s -- --upgrade
```

Or run `ados update`, which re-runs the installer upgrade for you:

```bash
ados update
```

Both preserve `/etc/ados/config.yaml` and your pairing state. See [Updating the Agent](/drone-agent/updating) for details.

## Installer flags

The bootstrap passes everything after `bash -s --` straight to the installer.
The parser rejects an unrecognised flag and aborts before touching the box, so
a guessed flag fails the install rather than being ignored.

**Identity**

| Flag | Effect |
|---|---|
| `--profile <drone\|ground_station\|workstation\|compute>` | Pin the node profile instead of auto-detecting. |
| `--name <hostname>` | Set the node's hostname, which is also its `.local` mDNS name. |
| `--pair <code>` | Pair to a Mission Control account during install. A bare positional argument is the same thing. On a box that is already installed, a bare code does a fast re-pair rather than a reinstall. |

**Install mode**

| Flag | Effect |
|---|---|
| `--upgrade` | Upgrade in place, keeping config and pairing state. |
| `--force` | Clear checkpoints and reinstall from scratch. |
| `--uninstall` | Remove the agent. |
| `--status` | Print install status and exit. |
| `--no-reboot` | Never take the single automatic reboot. Staged work (a camera or display overlay, an I2C dtparam) is then reported as `degraded` and named, instead of applying silently. |

**Source**

| Flag | Effect |
|---|---|
| `--branch <name>` | Install from a git branch. Development path. |
| `--channel <stable\|edge>` | Release channel. |
| `--version <ver>` | Pin an explicit agent version. |
| `--ref <commit>` | Pin the agent package and the prebuilt binaries to one revision, fetched from that commit's `rev-<sha>` release. Requires `--channel edge`. |
| `--artifacts <dir>` | Install service binaries from a directory of locally built artifacts instead of fetching them. Each file needs its `<name>.sha256` beside it; a service the directory does not carry still comes from the release. Requires `--channel edge`, not combinable with `--ref`, Linux only. |

<Warning>
`--ref` with `--channel stable` is refused with exit code 2 before any download. The stable channel resolves a wheel from a `v<X.Y.Z>` tag, which addresses a version and not a commit, so there is no per-revision wheel to pin. Use `--channel edge --ref <commit>`.
</Warning>

**Hardware**

| Flag | Effect |
|---|---|
| `--display <hint>` | Display hardware hint. |
| `--camera <hint>` | Camera hardware hint. |
| `--no-rtl-driver` | Skip the RTL8812EU radio driver build. Use this on a node with no long-range radio: the build takes minutes and fails on missing kernel headers. |

**Extensions**

| Flag | Effect |
|---|---|
| `--world-engine`, `--no-world-engine` | Install, or skip, the first-party [World Engine](/drone-agent/extensions/world-engine) extension (3D world model and compute offload). Without either flag the profile decides: on for `workstation` and `compute`, off for `drone` and `ground_station`. The last of the two flags wins. A failed extension install warns with the manual command and does not abort the node install. |

**Unattended**

| Flag | Effect |
|---|---|
| `-y`, `--yes` | Accept the detected defaults and skip the interactive onboarding wizard. |
| `--non-interactive` | Never prompt. Forces the silent, flag-driven install. |
| `--wifi-ssid <ssid>` | Join this Wi-Fi network during the install, so the wired cable can be unplugged afterwards. The join never touches the interface your SSH session rides on. |
| `--wifi-pass <password>` | Password for `--wifi-ssid`. Omit for an open network. |
| `-k`, `--plugin-key <path>` | Copy an operator or OEM extension trust key into `/etc/ados/plugin-keys/`. Repeatable. |

**Output**

| Flag | Effect |
|---|---|
| `--plain` | Escape-free line output, no animation or colour. |
| `--quiet` | Only the final summary, plus errors. |
| `--json` | Machine output on stdout, no progress UI. |
| `--no-color` | Disable colour in the progress UI. |
| `--ascii` | ASCII glyph fallback instead of Unicode box drawing. |
| `-h`, `--help` | Print usage and exit. |

On a fresh interactive install with none of the identity flags set, an
onboarding wizard walks through setup. It is skipped automatically when a
decisive flag is given, under `--json` or `--quiet`, or when no terminal is
attached.

A fully unattended provisioning run looks like this:

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh \
  | sudo bash -s -- \
    --non-interactive --yes \
    --profile drone --name field-01 \
    --wifi-ssid mycompany-fleet --wifi-pass '<passphrase>' \
    --plugin-key /root/example-oem-signing.pem \
    --json
```

## Install from source

For contributors and developers who want to modify the agent code:

```bash
# Clone the repo
git clone https://github.com/altnautica/ADOSDroneAgent.git
cd ADOSDroneAgent

# Create a virtual environment
python3.11 -m venv .venv
source .venv/bin/activate

# Install in development mode
pip install -e ".[dev]"

# Check the CLI surface
ados --help
```

<Warning>
For deployment on actual hardware, always use the install script instead of `pip install -e`. The install script catches packaging bugs (missing data files, broken entry points) that editable installs skip silently. Editable installs are for local development on your laptop only.
</Warning>

## Install on macOS

macOS gets a rootless, per-user workstation node. Run the same bootstrap
**without** `sudo`; the script refuses a root run with exit code 2 and explains
why. There is no prebuilt Mach-O installer, so the Mac path builds the installer
from source (it ensures the Rust toolchain first) and defaults to
`--profile workstation`.

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh | bash
```

The Rust installer registers per-user LaunchAgents under `$HOME/.ados`,
including the plugin host, which runs each extension as its own LaunchAgent in
`~/Library/LaunchAgents`. The World Engine is installed by default, as on any
workstation. A workstation node has no systemd, no WFB radio and no GPIO, so
hardware behaviour must be verified on Linux hardware.

## Uninstall

On Linux (removes services, binary, and data, keeps config):

```bash
ados uninstall
```

To remove everything including config:

```bash
ados uninstall --purge
```

On macOS:

```bash
ados uninstall
```

The CLI auto-detects whether you installed with pip, pipx, or uv and uses the matching uninstall command.

## Directory layout after install

```
/opt/ados/                  # Installation root
  venv/                     # Python virtual environment
  bin/                      # Prebuilt Rust service binaries
  models/                   # Vision engine models (if Tier 4)

/etc/ados/                  # Configuration
  config.yaml               # Main config file
  device-id                 # Unique device identifier
  pairing.json              # Cloud pairing state
  certs/                    # TLS certificates (if enabled)

/var/ados/                  # Runtime data
  logd/                     # Black-box logging store (logs.db)
  recordings/               # Video recordings
  logs/flights/             # Flight log archive

/run/ados/                  # Unix domain sockets (tmpfs)
  mavlink.sock              # Binary MAVLink IPC
  state.sock                # JSON telemetry IPC

/usr/local/bin/ados         # CLI symlink
```

## Verifying the installation

After install, check that everything is running:

```bash
# Check service and setup status
ados status

# Open the terminal status page and setup URL list
ados
```

`ados` shows the local setup webapp URL, service state, MAVLink state, video
state, network URLs, and remote access state. Open the setup URL in a browser to
finish onboarding.
