Video is a drone-profile page at `/video`: live stream, encoder configuration, camera assignment, and latency probe.

<Frame caption="Video with a live stream.">
  ![Agent dashboard Video page with the live WebRTC player above the pipeline, codec and resolution readout](/images/drone-agent/dashboard/video.png)
</Frame>

## Player

The player streams from the agent itself; the cloud relay is not involved.

- **Transport chip:** HLS or WebRTC, shown when the agent publishes both. The drone tries WebRTC (WHEP) first; a ground station starts on HLS.
- **State badge:** `live · webrtc`, `live · hls`, `webrtc · frozen` or `hls · frozen`, `connecting`, `snapshot` (still frame from `GET /api/video/snapshot`), `error` or `idle`.
- **g2g row:** glass-to-glass latency, when measured.
- Playback pauses while the player is off screen. If a transport fails, the player re-dials, falls back to HLS, then to a still frame.

**Snapshot** downloads the current frame as `ados-snapshot-<ms>.jpg` with its capture time. **Rescan** re-reads the camera list and config.

## Encoder

Encoder shows the configured codec, resolution, frame rate (fps) and bitrate. The live stream values are on the player above.

## Radio

A read-only view of the WFB link: channel, band, MCS index, FEC ratio, adaptive FEC, tx power and preset.

## Link tuning

Edits the live link:

| Control | Values |
| --- | --- |
| Preset | conservative, balanced, aggressive |
| FEC (k / n) | 8/16, 8/14, 8/12, 8/10, 4/12 |
| MCS rate | the MCS indexes the radio supports |
| Adaptive error correction | on or off |

Changes apply to the live link through `POST /api/video/config`, and the card re-reads the config.

## Latency

latest, ewma, samples and source. The source reads unavailable until the pipeline produces timing samples.

## Cameras detected

The agent's latest camera enumeration, refreshed whenever the video pipeline (re)starts. Each row shows the camera label, device path and type. With none it reads "No cameras detected. Plug in a USB UVC camera or a MIPI-CSI module and Rescan."

## Data sources

| Endpoint | Used for |
| --- | --- |
| `GET /api/video/cameras` | Cameras detected |
| `GET /api/video/config` | Encoder, Radio, Link tuning |
| `POST /api/video/config` | Link tuning |
| `GET /api/video/latency` | Latency |
| `GET /api/video/snapshot` | Snapshot and the still-frame fallback |
| `GET /api/v1/setup/status` | the WHEP and HLS URLs |
| `GET /api/wfb` | radio state |

## Troubleshooting

<AccordionGroup>
  <Accordion title="The player stays on connecting or snapshot">
    An idle player names the reason: "No camera detected.", "No stream published." or "Pipeline idle." For a camera problem see Cameras detected and [Diagnostics](/drone-agent/dashboard-diagnostics). If the pipeline runs but the stream will not play, switch the transport chip to HLS or press **Retry**.
  </Accordion>
  <Accordion title="A camera is missing">
    Plug it in and press **Rescan**. The list itself refreshes when the video pipeline restarts; restart the video service from Diagnostics if needed.
  </Accordion>
</AccordionGroup>
