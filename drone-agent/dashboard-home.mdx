Home is the landing page at `/` and `/home`. It opens with the **Enter Cockpit** banner and the Region chip, then six status tiles, four live charts, and a stack of panels that depends on the profile.

## Status tiles

| Tile | Shows |
| --- | --- |
| MAV (FC for MSP firmware) | Satellites once GPS reports, else linked or off. A Betaflight or iNav FC reads `FC linked · <variant> · msp`. |
| HW | Required components ok/total, with the names of any that fail. |
| VID | Bitrate, or the video pipeline state. |
| NET | Uplink kind and RSSI in dBm. |
| CLD | The chosen cloud posture (local, cloud, self_hosted). The relay's live link state is not reported here. |
| PAIR | `paired · linked` once the node is paired with Mission Control (over the LAN or the relay), otherwise the current pairing code, `n/a · local mode` for an unpaired local node, or `unpaired`. |

The tiles are status only; they do not link to other pages.

## Charts

Four 60-second charts: Battery (V), RC RSSI (%), Bitrate (kbps), CPU (%). Headlines show the current value, or a dash when the source is gone. CPU comes from `GET /api/status`; the others come from the dashboard snapshot.

## Panels by profile

<Tabs>
  <Tab title="Drone">
    <Frame caption="Home on a drone-profile node with live video.">
      ![Agent dashboard Home on a drone node showing tiles, charts, Video and Flight Controller panels](/images/drone-agent/dashboard/home.png)
    </Frame>

    Panels, in order:

    - **Video:** the live stream with an HLS / WebRTC transport chip. The drone tries WebRTC (WHEP) first. If neither plays, the panel falls back to a still frame from `GET /api/video/snapshot`. See [Video](/drone-agent/dashboard-video#player).
    - **Flight Controller:** vehicle, firmware, mode with ARMED or disarmed, gps (sats · hdop), battery (V · %), rc, port. A Betaflight or iNav FC shows firmware, `telemetry via MSP` and port.
    - **WFB Transmit:** interface, channel (MHz), bandwidth, tx power and its maximum, MCS, domain, bitrate, packets, restarts. See [WFB Transmit](/drone-agent/dashboard-transmit).
    - **Cloud Relay:** mode, broker, status post and Pairing. In local posture it reads "Relay disabled. Mission Control reaches this drone over the LAN."
    - **Hardware:** detected components with their state, and a **Rescan** button.
    - **Network:** the active uplink and its interfaces.
    - **Services:** each agent unit with its state.
  </Tab>
  <Tab title="Ground station">
    <Frame caption="Home on a ground station in the direct role.">
      ![Agent dashboard Home on a ground station showing tiles, charts, Video and WFB Receive panels](/images/ground-agent/dashboard/home.png)
    </Frame>

    Same tiles and charts as the drone. Panels: Video, WFB Receive, Cloud Relay, then Mesh (relay, receiver) and Sources (receiver), Hardware, Network, Services.

    - **Video** tries HLS first and reads "Waiting for WFB stream from drone." until frames arrive.
    - **WFB Receive** fields are on [WFB Receive](/ground-agent/dashboard-receive#fields).
    - **Mesh** and **Sources** fields are on [Mesh and sources](/ground-agent/dashboard-mesh).

    The page subtitle follows the ground role:

    | Role | Subtitle |
    | --- | --- |
    | direct | Direct ground node. Live receive metrics for the drone link. |
    | relay | Forwarding the drone link. Live receive metrics, mesh state, and gateway election. |
    | receiver | Aggregating relays into one stream. Live receive metrics, mesh state, and per-source FEC. |
  </Tab>
</Tabs>

## Data sources

| Endpoint | Used by | Interval |
| --- | --- | --- |
| `GET /api/v1/dashboard/snapshot` | tiles, charts, Flight Controller, Hardware, Network | 1 s |
| `GET /api/v1/setup/status` | layout, video URLs | 8 s |
| `GET /api/status` | CPU chart, top bar | 5 s |
| `GET /api/wfb` | WFB Transmit, WFB Receive | 2 s |
| `GET /api/cloud/link` | Cloud Relay | 5 s |
| `GET /api/services` | Services | 4 s |
| `GET /api/video/snapshot` | Video still-frame fallback | on fallback |
| `POST /api/v1/setup/hardware-check/refresh` | Hardware **Rescan** | on click |
| `GET /api/v1/setup/nudges` | cloud-posture nudge | on load |
| `GET /api/v1/ground-station/mesh` | Mesh (ground) | 2 s |
| `GET /api/v1/ground-station/wfb/receiver/combined`, `.../relays` | Sources (ground receiver) | 2 s |

## Troubleshooting

<AccordionGroup>
  <Accordion title="A red HW tile">
    The tile names the failing required component. Open the Hardware panel for its detail and fix hint, fix the connection, then press **Rescan**.

    <Frame caption="Home with a required component missing.">
      ![Agent dashboard Home with a red status dot on the HW tile reading 2/3 and naming the missing Camera](/images/drone-agent/dashboard/home-setup-incomplete.png)
    </Frame>
  </Accordion>
  <Accordion title="Camera does not appear">
    The Video panel reads "No camera detected." and the Video page reads "No cameras detected." Plug the camera in and open Video → **Rescan**. If it still does not appear, check Peripherals and restart the video service from Diagnostics.
  </Accordion>
  <Accordion title="Cloud Relay says awaiting code…">
    The node is in a cloud posture, unpaired, and you are not on its own network. Open the dashboard from the node's LAN, hotspot or USB link to see the code.
  </Accordion>
</AccordionGroup>
