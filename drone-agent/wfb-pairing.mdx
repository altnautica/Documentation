WFB-ng pairing (the bind) gives a drone and a ground station the two halves of one radio key pair. It runs over the local radio with no internet. The cloud relay never carries the radio key. For the link itself (channels, power, automation), see [WFB-ng](/drone-agent/wfb-ng).

## How a bind works

The bind runs in `ados-supervisor`, because it has to stop and restart the radio units, and the supervisor survives every service restart.

<Steps>
  <Step title="Open the bind window">
    The supervisor checks that the upstream bind files (`/etc/bind.key`, `/etc/bind.yaml`) exist, stops the normal radio unit (`ados-wfb` on a drone, `ados-wfb-rx` on a ground station) and starts the upstream wfb-ng bind profile (`wifibroadcast@drone_bind` or `wifibroadcast@gs_bind`).
  </Step>
  <Step title="Bring up the bind tunnel">
    The two radios form a temporary IP tunnel over WFB-ng. The upstream bind scripts (`wfb_bind_server.sh` on the drone, `wfb_bind_client.sh` on the ground station) transfer the key pair across it on TCP port 5555.
  </Step>
  <Step title="Apply the keys">
    The agent checks the key is a 64-byte libsodium key file and writes the role's key atomically with mode `0600`: `/etc/ados/wfb/tx.key` on the drone (from `/etc/drone.key`), `/etc/ados/wfb/rx.key` on the ground station (from `/etc/gs.key`). It records a blake2b-8 fingerprint, the peer, the time and the fleet slot under `video.wfb`, and disarms auto-pair.
  </Step>
  <Step title="Restart the radio">
    The normal radio unit and `ados-swarmbus` restart with the new keys. The swarm bus restarts because its fleet key derives from `/etc/drone.key`, which the bind just rewrote.
  </Step>
</Steps>

### Bind states

`GET /api/wfb/pair/local-bind` and `ados radio status` report the session state. Each active phase has its own no-progress budget; a phase parked past it fails the session and puts the radio back under its normal unit.

| State | Meaning | Budget |
|---|---|---|
| `idle` | No bind running. | n/a |
| `opening_tunnel` | Bind profile starting, waiting for the tunnel interface. | 30 s |
| `waiting_peer` | Tunnel up, waiting for the other rig. | 120 s |
| `transferring_keys` | Upstream scripts exchanging keys. | 90 s, shared with `applying_keys` |
| `applying_keys` | Writing key files and pair state. | 90 s, shared with `transferring_keys` |
| `restarting_services` | Normal radio and swarm bus restarting. | 60 s |
| `paired` | Bind succeeded. | n/a |
| `failed` | A step failed or a budget ran out; `error` says which. | n/a |
| `aborted` | The session was cancelled. | n/a |

Only one bind runs at a time. A second request while one is active answers `409`.

## Auto-pair on first boot

`video.wfb.auto_pair_enabled` defaults to `true`. While it is armed and the role's key file is absent, the supervisor runs a bind about 15 s after boot and then retries every 3-7 s. A bind is a rendezvous, so the short randomised retry keeps the two rigs' windows overlapping no matter when each one booted.

Power on a fresh drone and a fresh ground station near each other and they bind without operator action. A successful bind disarms auto-pair, so the rig never silently re-binds to another device after an unpair.

One exception re-arms it: a key whose fingerprint has never been confirmed working, for example a key left over from a ground station that was since reflashed. A key that has worked once is never re-armed.

```bash
ados radio pair status       # paired, peer, fingerprint, auto-pair state
ados radio pair auto off     # stop auto-pair
ados radio pair auto on      # re-arm (only when unpaired)
```

## Key handling by role

- **Drone** (`agent.profile: drone`): holds `tx.key`, the transmit half.
- **Ground station** (`agent.profile: ground_station`): holds `rx.key`, the receive half. A ground station holds one receive key for its fleet; drones are distinguished by `video.wfb.fleet_slot`, which the ground station issues at bind time.

The two files are complementary halves, not copies. To check that two rigs belong together, compare the fingerprint `ados radio pair status` prints on each. See [Key model](/drone-agent/wfb-ng#key-model) for the file layout and [Swarm bus](/drone-agent/swarm-bus#fleet-addressing) for the fleet key.

## Manual bind

A manual bind opens the same local-radio bind window (`ados radio pair local`, or the Mission Control **Radio** controls); run it on both nodes within the window.

```bash
ados radio pair local                 # role inferred from the profile
ados radio pair local --role gs       # override: drone | gs
```

The command waits for the session to end and prints the fingerprint on success. In Mission Control, open the node's **Radio** panel and use **Open local bind window** in the **Pairing** card; the same card has **Unpair**, **Stop auto-pair** and **Re-arm auto-pair**.

Use a manual bind to re-key a pair, to replace a ground station, or when auto-pair is off. To start over:

```bash
ados radio pair unpair --yes
```

<Note>
Opening a bind window stops the normal radio unit, and unpair wipes the key files. Both are refused while the vehicle is armed (`409`, `E_ARMED`).
</Note>

## When the radios cannot bind

After 10 failed attempts on a node with a cloud relay configured (`server.mode` cloud or self-hosted), the node reports `failover_state: cloud_relay` and Mission Control reaches it through the cloud relay instead. The radio key is never distributed through the cloud. The local bind keeps retrying, because the peer may power on at any time.

```bash
ados radio pair failover-status
```

`failover_state` is `local`, `cloud_relay` or `failed`. See [Cloud relay](/drone-agent/cloud-relay).

## REST surface

| Route | Verb | Purpose |
|---|---|---|
| `/api/wfb/pair` | GET | Pair state: paired, role, peer, fingerprint, auto-pair. |
| `/api/wfb/pair/auto-pair` | PUT | Arm or disarm auto-pair (`{"enabled": true}`). |
| `/api/wfb/pair/local-bind` | POST | Open a local bind window; returns the terminal session. |
| `/api/wfb/pair/local-bind` | GET | Current bind session state. |
| `/api/wfb/pair/unpair` | POST | Wipe the key files and clear pair state. |
| `/api/wfb/pair/failover-status` | GET | `local`, `cloud_relay` or `failed`. |

All routes require the `X-ADOS-Key` header. A ground station also serves the fleet and phone-invite routes under `/api/v1/ground-station/wfb/` (`invite`, `invite/{id}/approve`, `invite/{id}/reject`, `pair`, `pair/{device_id}`). The full list is in the [REST API](/drone-agent/rest-api) reference.

## Diagnose a bind

The Black Box store is off by default, so the journal is the record:

```bash
sudo journalctl -u ados-supervisor --grep bind -n 50
ados radio pair status
ados diag link
```

With the [Black Box store](/drone-agent/black-box) turned on, the same events are queryable:

```bash
ados logs query --source ados-supervisor --text bind --since -1h
ados logs query --kind events --event-kind wfb.pair.failover --since -1d
```

A `failed` session with a tunnel timeout usually means the other rig was not in a bind window at the same time, or the two radios are on different channels or regulatory domains. See [Operating region](/drone-agent/wfb-ng#operating-region).
