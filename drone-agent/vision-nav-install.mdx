# Install on a drone

This page walks the shortest path from a fresh drone to a vision-held hover: pick a mode, wire the hardware, install the plugin, configure it, engage it, and arm. Each step links to the full reference.

Vision Navigation installs one drone at a time. Each install carries its own permission grants and its own per-drone configuration, and the plugin runs only on the agent of the drone you picked. A fleet of ten drones can run it on three of them without touching the other seven.

## 1. Pick a mode

<Steps>
  <Step title="Downward camera and a rangefinder?">
    Use `optical_flow`. The default GPS-denied path for low-altitude hover and waypoint flight.
  </Step>
  <Step title="Downward camera, no rangefinder?">
    Use `optical_flow_degraded`. Same tracker; scale comes from the barometer instead. Lower accuracy, and the estimator reports `degraded` whenever it falls back to a fixed height.
  </Step>
  <Step title="Just checking the hardware?">
    Use `off`. The plugin loads and reports health but sends nothing to the flight controller.
  </Step>
</Steps>

See [Modes](/drone-agent/vision-nav-modes) for the side-by-side comparison and the pre-arm checks.

## 2. Wire the hardware

The minimum:

- A companion computer running the ADOS Drone Agent 0.99.125 or newer, on a [supported board](/drone-agent/vision-nav-overview#supported-boards).
- A downward-facing USB UVC or CSI camera. The agent's vision host must already be capturing it; the plugin reads frames from the shared vision bus.
- A rangefinder if you picked `optical_flow`. The simplest path is one already wired to the flight controller, which forwards it as `DISTANCE_SENSOR`.
- A flight controller on ArduPilot 4.5+, PX4 1.14+, or iNav 7.0+. Betaflight is not supported.

[Hardware](/drone-agent/vision-nav-hardware) covers camera and rangefinder picks, mounting, and wiring.

## 3. Install the plugin

1. In Mission Control, open the drone from the fleet and switch to the **Extensions** tab in the drone detail panel.
2. Install the signed `com.altnautica.vision-nav` archive (a `.adosplug` file from the [ADOSExtensions releases](https://github.com/altnautica/ADOSExtensions/releases), or its URL).
3. Review the summary and the permission list, approve, and wait for the install to finish.

The install dialog itself (transport choice, signature check, progress) is the same for every extension and is covered in [Installing extensions](/mission-control/installing-plugins). From a shell on the drone, `ados plugin install <source>` does the same job; see [Plugins](/drone-agent/plugins).

The plugin carries a **high** risk badge because it feeds a measurement into the flight controller's state estimator.

### Permissions it requests

Every grant has a call site in the plugin's code.

| Half | Permission | Why |
|---|---|---|
| Agent | `vision.frame.read` | Read normalized frames from the shared vision frame bus. |
| Agent | `hardware.uart`, `hardware.i2c` | Talk to a rangefinder wired to the companion. |
| Agent | `mavlink.read`, `mavlink.write` | Read `RAW_IMU`, `DISTANCE_SENSOR`, `TIMESYNC`, and altitude messages; send `OPTICAL_FLOW_RAD`, `DISTANCE_SENSOR`, `TIMESYNC`, and `HEARTBEAT`. |
| Agent | `mavlink.component.peripheral` | Register MAVLink component 198. |
| Agent | `telemetry.extend` | Add the `navigation` block to the agent heartbeat. |
| Agent | `event.publish` | Publish the engage state on `navigation.engage`. |
| Mission Control | `ui.slot.node-detail-tab` | The **Vision Nav** tab on the drone detail panel. |
| Mission Control | `ui.slot.flight-skill` | The **Engage** cockpit Skill. |
| Mission Control | `telemetry.subscribe.navigation` | Read the `navigation` heartbeat block. |

## 4. Configure it

Open the plugin's per-drone configuration from the Extensions tab. The fields that matter for a first flight:

| Key | Set to |
|---|---|
| `mode` | `optical_flow` or `optical_flow_degraded` (default `off`) |
| `camera.orientation` | `downward`, or `auto` when the board profile declares the camera role |
| `rangefinder.topology` | `fc` if the flight controller owns the rangefinder, `companion` for a TF-Luna on a companion UART, `none` otherwise |
| `firmware.type` | `ardupilot`, `px4`, or `inav` |

The plugin refuses an optical-flow mode with a `forward` or `side` camera. A configuration that fails validation leaves vision navigation disengaged rather than falling back to some other mode. A configuration change restarts the plugin with the new mode.

Then set the flight controller parameters for your firmware. [Configure optical flow](/drone-agent/vision-nav-optical-flow) has every key and every parameter.

## 5. Calibration (optional)

Optical flow works without a camera calibration file. If you have a Kalibr `camchain.yaml` for this camera and IMU, copy it into the plugin's data directory and the agent uses its `timeshift_cam_imu` to pair each frame with the right gyro sample. See [Calibration](/drone-agent/vision-nav-calibration).

## 6. Engage, check pre-arm, and fly

The plugin contributes an **Engage** Skill to the cockpit (default key `Shift+N`). It toggles the per-drone `active` flag and asks for confirmation before it engages. When disengaged, the plugin runs as `off`: nothing reaches the flight controller and the FC falls back to its own sources. The Skill reflects the true state from the agent's `navigation.engage` event.

Open the **Vision Nav** tab on the drone detail panel. The pre-arm card shows one row per check for the active mode, and the whole card reads **Ready** only when every row is green.

When every row is green:

1. Confirm the flight controller's EKF is set to use optical flow for horizontal velocity (`EK3_SRC1_VELXY = 5` on ArduPilot, `EKF2_OF_CTRL` on PX4, `nav_use_optflow_for_poshold = ON` on iNav).
2. Make sure the EKF has an origin. Without GPS, ArduPilot waits for one; set it from your ground station before arming.
3. Arm and take off to 1.5 to 3 m for the first hop.

If something goes wrong, see [Troubleshooting](/drone-agent/vision-nav-troubleshooting).

## Uninstall

The Extensions tab removes the plugin per drone: it stops the process and clears the plugin's state on the agent. The drone returns to its baseline navigation (GPS on ArduPilot or PX4). Remember to point the EKF source parameters back at GPS.

## Install troubleshooting

- **The install is refused.** Check that the agent is 0.99.125 or newer, Mission Control is 0.56.0 or newer, and the drone's board is in the [supported list](/drone-agent/vision-nav-overview#supported-boards).
- **The plugin runs but the Vision Nav tab stays empty.** The plugin isn't getting frames or the heartbeat isn't reaching Mission Control. Check that the agent's vision host is capturing the camera, then read the plugin's logs with `ados plugin logs com.altnautica.vision-nav`.
- **The mode card shows no modes.** The card lists only what the agent advertises; it stays empty until the first heartbeat arrives.
