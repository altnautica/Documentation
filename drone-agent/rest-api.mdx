# REST API

Port 8080 is owned by the native Rust front (`ados-control`, an axum server). It serves migrated routes directly and reverse-proxies the rest to a residual FastAPI on an internal Unix socket (`/run/ados/api-internal.sock`). From a client's point of view it is one HTTP API for status, telemetry, commands, configuration, video, pairing, and everything else the agent can do.

The API is the backbone that the CLI, TUI, and Mission Control all talk to.

Callers do not need to know which process answers a given route. Treat `:8080` as one API; the internal boundary behind it is not a contract and it moves.

## Base URL

```
http://<drone-ip>:8080
```

On the drone itself: `http://localhost:8080`

## Authentication

Most endpoints require the `X-ADOS-Key` header. The key is generated during pairing and stored at `/etc/ados/pairing.json`.

```bash
curl http://localhost:8080/api/status \
  -H "X-ADOS-Key: sk_live_your_key_here"
```

A few endpoints are exempt from auth (like `/api/pairing/info`) so that unpaired agents can still be discovered and paired.

## Route domains

The API is organized by domain.

| Domain | Prefix | Purpose |
|--------|--------|---------|
| Status | `/api/status`, `/api/status/full` | Agent status, board, FC, health |
| Configuration | `/api/config` | Read and write configuration |
| Config schema | `/api/config/schema` | The build-time-embedded shape of the whole config surface. Build a settings UI against this. |
| Commands | `/api/command`, `/api/commands` | Send MAVLink commands and list supported commands |
| Telemetry | `/api/telemetry` | Cached telemetry snapshot |
| Parameters | `/api/params`, `/api/params/{name}` | FC parameter reads and writes through the cache |
| Video | `/api/video` | Pipeline config, snapshot, recording |
| Diagnostics | `/api/diag/video` | Per-hop video pipeline verdict |
| WFB-ng | `/api/wfb` | Link stats, channel, pairing |
| MAVLink signing | `/api/mavlink/signing` | MAVLink2 signing capability and FC enrollment |
| Pairing | `/api/pairing` | Pair, unpair, info, code |
| Plugins | `/api/plugins`, `/api/v1/plugins/catalog` | Extension lifecycle, install, list, perms, config, state, and each extension's own API under `/api/plugins/{id}/x/` |
| Services | `/api/services` | Systemd service control |
| System | `/api/system`, `/api/v1/diagnostics` | Reboot, shutdown, diagnostics, resource reads |
| Fleet | `/api/fleet` | Fleet enrollment and peers |
| Swarm | `/api/swarm/neighbors` | The swarm neighbour table |
| MCP | `/api/mcp/status`, `/api/mcp/tokens`, `/api/mcp/revoke` | AI-control token posture and lifecycle |
| Peripherals | `/api/peripherals` | USB devices, sensors |
| Vision | `/api/vision`, `/api/vision/models` | Vision state, detections, model registry |
| Logs | `/api/logs`, `/api/observability` | Log retrieval (see also the `ados-logd` query API) |
| Network | `/api/v1/network` | MAC pinning, WiFi client |
| Ground station | `/api/v1/ground-station` | Ground-station status, network, PIC, mesh, UI, recording |
| WHEP | `/whep` | WebRTC video playback signaling |
| Setup | `/api/setup`, `/setup` | First-boot setup wizard webapp |

The generated route table lives at `docs/api-surface.md` in the agent repo and a
repository check resolves every client path literal against it, so a route that
is documented here and absent there is a bug in one of the two.

## Extension lifecycle

The native front serves the whole extension lifecycle on every profile,
including a macOS workstation. There is no Python behind these routes.
Errors use one envelope, `{"ok": false, "code": N, "kind": "...", "detail": "..."}`.

| Method | Path | What it does |
|---|---|---|
| `GET` | `/api/v1/plugins/catalog` | The first-party catalog bundled with this agent build. |
| `GET` | `/api/plugins` | Installed extensions: `{installs: [...]}`. |
| `POST` | `/api/plugins/parse` | Preview an uploaded archive (multipart `file`): manifest, signer, risk, permissions. Nothing is written. |
| `POST` | `/api/plugins/install` | Install an uploaded archive. `?requested_permissions=a,b` grants what the operator approved; `?job_id=` streams progress. |
| `POST` | `/api/plugins/parse_from_url` | Preview an archive from an allowlisted HTTPS URL. Returns its sha256 so the install can pin it. |
| `POST` | `/api/plugins/install_from_url` | Install from an allowlisted HTTPS URL: `{url, expected_sha256?, requested_permissions?, job_id?, from_catalog}`. A catalog install must pin a sha256. |
| `POST` | `/api/plugins/install_builtin` | Install one of the built-in plugins the agent ships: `{plugin_id}`. |
| `WS` | `/api/plugins/jobs/{job_id}` | Install progress for a `job_id` passed to an install call. |
| `GET` | `/api/plugins/{id}` | The install record, granted capabilities and the manifest summary with the GCS block. |
| `DELETE` | `/api/plugins/{id}` | Stop and uninstall. |
| `GET` | `/api/plugins/{id}/manifest` | The installed `manifest.yaml`, byte for byte. |
| `GET` | `/api/plugins/{id}/attestation` | `{signature, files: [{path, sha256, payload?}]}`: the archive signature and every attested file's digest, payloads marked. Mission Control checks an inline GCS module against it before loading it. |
| `GET` | `/api/plugins/{id}/readiness` | `{ok, plugin_id, services}`: each declared service that runs on this node, probed now. |
| `GET` | `/api/plugins/{id}/gcs/{path}` | One file from the extension's GCS half, so a LAN-paired Mission Control mounts it with no cloud. |
| `POST` | `/api/plugins/{id}/grant` | Grant one declared permission: `{permission_id}`. |
| `DELETE` | `/api/plugins/{id}/perms/{permission_id}` | Revoke a permission. Takes effect at runtime. |
| `POST` | `/api/plugins/{id}/enable`, `/disable` | Start or stop the extension. |
| `POST` | `/api/plugins/{id}/pin`, `/unpin`, `/auto-update` | Update preferences. |
| `POST` | `/api/plugins/capability-token` | Mint a short-lived capability token for the GCS half. |
| `GET`, `PUT` | `/api/plugins/{id}/config` | Read the effective config, or write one key: `{key, value, scope?}`. |
| `GET` | `/api/plugins/{id}/state` | The extension's latest published state. |
| `POST` | `/api/plugins/{id}/tools/{tool}/invoke` | Run one of the extension's MCP tools. |
| any | `/api/plugins/{id}/x/{path}` | The extension's own HTTP API. |

### Extension HTTP passthrough

An extension that declares `agent.http: true` serves its own API on a Unix
socket the plugin host creates for it. `/api/plugins/{id}/x/{path}` forwards
`GET`, `POST`, `PUT`, `PATCH` and `DELETE` there as `/{path}`, keeping the
query string, and upgrades WebSockets. The pairing key authenticates the
request before it is forwarded, and the route also works through a ground
station's relay proxy. When the extension is not serving, the answer is `503`
with `{"detail": "plugin <id> is not serving HTTP"}`.

```bash
curl -s -H "X-ADOS-Key: $KEY" \
  http://localhost:8080/api/plugins/com.altnautica.world-engine/x/atlas/readiness
```

## Common endpoints

### Status

```bash
# Full agent status
curl http://localhost:8080/api/status \
  -H "X-ADOS-Key: $KEY"
```

Response:

```json
{
  "version": "<agent version>",
  "uptime_seconds": 3847,
  "board": {
    "name": "Radxa ROCK 5C Lite (RK3582)",
    "tier": 4,
    "soc": "RK3582"
  },
  "fc_connected": true,
  "fc_port": "/dev/ttyS0",
  "fc_baud": 921600,
  "health": {
    "cpu_percent": 12.3,
    "memory_percent": 34.2,
    "disk_percent": 41.8,
    "temperature": 52.3
  }
}
```

```bash
# Consolidated full status (single request, replaces 4 separate calls)
curl http://localhost:8080/api/status/full \
  -H "X-ADOS-Key: $KEY"
```

### Configuration

```bash
# Read full config
curl http://localhost:8080/api/config \
  -H "X-ADOS-Key: $KEY"

# Set a value
curl -X PUT http://localhost:8080/api/config \
  -H "X-ADOS-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"key": "mavlink.baud_rate", "value": "115200"}'
```

### Video

```bash
# Video pipeline status
curl http://localhost:8080/api/video \
  -H "X-ADOS-Key: $KEY"

# Capture snapshot
curl -X POST http://localhost:8080/api/video/snapshot \
  -H "X-ADOS-Key: $KEY"
```

### Parameters

```bash
# Read cached FC parameters
curl http://localhost:8080/api/params \
  -H "X-ADOS-Key: $KEY"

# Read a single parameter
curl http://localhost:8080/api/params/RC1_MIN \
  -H "X-ADOS-Key: $KEY"
```

### Pairing

```bash
# Check pairing status (no auth required)
curl http://localhost:8080/api/pairing/info

# Unpair
curl -X POST http://localhost:8080/api/pairing/unpair \
  -H "X-ADOS-Key: $KEY"
```

### Services

```bash
# List all systemd services and their states
curl http://localhost:8080/api/services \
  -H "X-ADOS-Key: $KEY"
```

### Ground station

```bash
# Ground station status (only in ground-station profile)
curl http://localhost:8080/api/v1/ground-station/status \
  -H "X-ADOS-Key: $KEY"

# Network info
curl http://localhost:8080/api/v1/ground-station/network \
  -H "X-ADOS-Key: $KEY"

# PIC heartbeat

  -H "X-ADOS-Key: $KEY" \
  -H "Content-Type: application/json" \
  -d '{"client_id": "gcs-session-1"}'
```

## CORS

CORS is enabled by default with an allowlist, not a wildcard. The defaults cover the local Mission Control development origins (`localhost:4000`, `localhost:4001`). Add your own origins in config without dropping the defaults:

```yaml
security:
  api:
    cors_enabled: true
    cors_origins_extra: ["https://command.altnautica.com"]
```

The effective allowlist is the union of the built-in defaults, `cors_origins`, and `cors_origins_extra`.

## Interactive API docs

A standard install serves interactive documentation:

- **Swagger UI:** `http://localhost:8080/docs`
- **ReDoc:** `http://localhost:8080/redoc`

Both are present on a standard install and absent on a headless node. Check with
one request rather than reasoning about the build:

```bash
curl -o /dev/null -w '%{http_code}\n' http://localhost:8080/docs
```

`200` means they are there, `404` means this node does not serve them.

<Warning>
Do not build an integration against the shape of `/docs`. It documents one
internal process and its coverage moves. `GET /api/config/schema` is the stable,
always-present machine-readable surface: it returns the committed,
build-time-embedded shape of the config surface, so a schema-driven settings UI
renders without hand-written forms.
</Warning>
