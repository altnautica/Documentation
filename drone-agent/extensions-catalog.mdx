# Extensions catalog

These are the first-party extensions Altnautica publishes through the public [`ADOSExtensions`](https://github.com/altnautica/ADOSExtensions) repo. Each one ships as a signed `.adosplug` archive on GitHub Releases and installs from the Mission Control [Extensions tab](/mission-control/installing-plugins) on any drone you've connected. The archive carries a detached Ed25519 signature; the agent verifies it against the matching public key enrolled at `/etc/ados/plugin-keys/` and refuses the install if no enrolled key verifies it. First-party archives are signed with `altnautica-2026-A`.

Every extension is licensed GPL-3.0-or-later; hardware reference designs ship CC0 1.0.

## ADOS MAVLink Gimbal v2 Controller

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.mavlink-gimbal-v2` |
| Version | 1.3.0 |
| Risk | medium |
| Type | Hybrid (agent subprocess + GCS iframe) |
| Hardware | A MAVLink gimbal-manager gimbal on component 154 (optional) |
| FC firmware | ArduPilot or PX4 forwarding the gimbal-manager messages |
| Supported boards | any |

Drives a MAVLink gimbal-manager on component 154. Beyond manual pitch and yaw it runs an on-companion visual servo: click a detected subject in the cockpit and the gimbal keeps it centred. A lock-state gate stops commanding the moment the vision engine reports the subject uncertain or lost, and it never silently re-locks onto a different subject. Cockpit Skills arm the aim behaviour, recenter, point nadir, and switch between angle and rate control.

It speaks MAVLink Gimbal v2 only. There are no vendor serial drivers, so a gimbal that does not present a gimbal-manager to the flight controller is out of scope.

**Permissions:** MAVLink read and write, the gimbal component, vision detection subscribe, event publish and subscribe, MCP tool exposure.

**Resources:** 64 MB max RAM, 15% CPU, 8 PIDs.

## ADOS Vision Navigation

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.vision-nav` |
| Version | 0.4.0 |
| Risk | high |
| Type | Hybrid (Rust agent binary + GCS iframe) |
| Hardware | USB UVC global-shutter or rolling-shutter camera, or CSI via V4L2; optional rangefinder (TF-Luna, Garmin LIDAR-Lite, ST VL53L1X) |
| FC firmware | ArduPilot 4.5+, PX4 1.14+, iNav 7.0+ |
| Supported boards | cm4, cm5, rk3582, rk3588s2, rk3576, rpi5, pi-zero-2w |

Position hold when GPS is unreliable: indoors, under bridges, in urban canyons. A downward camera plus the flight controller's gyro produce a 30 Hz angular-flow measurement over MAVLink, so position-hold, loiter and missions keep working unchanged.

Three modes: optical flow with a rangefinder (low altitude over textured ground), optical flow without one (barometer or GPS height for scale, which drifts above 5 m), or Off. There is no visual-inertial odometry mode and no vendor VIO binary in the archive. Every tick the plugin checks itself; if flow quality drops or the scale source goes unhealthy it steps down the scale ladder and warns the GCS at each step, and a sustained degraded streak flips the companion node to CRITICAL.

**Permissions:** shared vision frame bus read (the plugin never opens a camera itself), UART and I2C for the rangefinder, telemetry extend, event publish, MAVLink read and write plus the peripheral component.

**Resources:** 512 MB max RAM, 80% CPU, 24 PIDs.

See the [Vision Navigation overview](/drone-agent/vision-nav-overview) for the full operator guide.

## ADOS Follow-Me

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.follow-me` |
| Version | 0.2.8 |
| Risk | high |
| Type | Hybrid (agent subprocess + GCS iframe) |
| Hardware | USB UVC or CSI camera bound to the vision pipeline; a gimbal is optional |
| FC firmware | ArduPilot or PX4 in a guided position-hold mode (ArduPilot Guided, PX4 Offboard/position) |
| Supported boards | cm4, cm5, rk3582, rk3588s2, rk3576, rpi5, cubie-a7s, a733, sun60iw2 |

Click a subject in the live video and the drone follows it at a fixed distance and height. A detector on the companion produces detections, the operator designates one, and the companion locks that track, projects its image position onto the ground and feeds the flight controller guided position setpoints at 6 Hz.

A lock-state gate stops commanding the instant the tracker reports the subject uncertain or lost, and it never silently re-locks onto a different subject. The Follow-Me Skill in the cockpit Skill Bar arms and disarms the behaviour. There is deliberately no start tool for an assistant: a follow begins only when an operator designates a subject.

**Permissions:** vision detection subscribe, MAVLink read and write, guided setpoint, event publish and subscribe, MCP tool exposure.

**Resources:** 128 MB max RAM, 25% CPU, 4 PIDs.

## ADOS SIYI Optical Pod

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.siyi-pod` |
| Version | 0.4.0 |
| Risk | high |
| Type | Agent subprocess + GCS iframe |
| Hardware | A SIYI pod (A2 mini, A8 mini, ZR10, ZR30, ZT6, ZT30) on the pod network `192.168.144.x`, or a TTL serial port |
| Supported boards | cm4, cm5, rk3582, rk3588s2, rk3576, rpi5, x86 |

Speaks the SIYI Gimbal Camera External SDK over UDP, TCP or TTL serial directly, so the agent drives what a stock autopilot mount cannot: thermal palette and gain, the laser rangefinder, and subject geolocation. On start it queries firmware and the hardware id, resolves that model's capability profile, and exposes only the controls the model supports.

Until the pod answers the identity query it is sent nothing at all. The negotiation retries on a fixed interval with no attempt cap, so a pod that is unpowered at boot comes online without a restart. Laser range plus gimbal angles plus the flight controller pose resolve a subject latitude and longitude that drops a marker on the map. Gimbal attitude and laser range are mirrored to the flight controller as standard MAVLink, so the built-in gimbal panel works too.

**Permissions:** outbound network, UART, MAVLink read and write, the gimbal and camera components, telemetry extend, video source set, event publish, MCP tool exposure.

**Resources:** 128 MB max RAM, 25% CPU, 4 PIDs.

## Installing one

From Mission Control:

1. Open the node from the fleet and switch to the **Extensions** tab.
2. Point the install dialog at the extension's `.adosplug`: paste the release URL or upload a downloaded file.
3. Approve the two-stage install dialog.

See [Installing extensions](/mission-control/installing-plugins) for the exact surface.

From the agent CLI, download first and install the local file. `ados plugin install` takes a path that already exists on the node; it does not fetch a URL.

```bash
curl -LO https://github.com/altnautica/ADOSExtensions/releases/download/<release>/<extension>.adosplug
ados plugin install ./<extension>.adosplug
```

The URL path runs through the GCS instead. See [Distribution: install from a URL](/developers/distribution-url-install).

The signature is verified against the keys in `/etc/ados/plugin-keys/` before the archive is unpacked.

## Submitting an extension

Community extensions land via the [hosted registry](/developers/distribution-registry) submission flow when the registry hits v1.0. Until then, first-party extensions live in the public [`ADOSExtensions`](https://github.com/altnautica/ADOSExtensions) repo and any plugin you build with the [SDK](/developers/sdk-python) installs cleanly via the local `.adosplug` path documented in [Distribution: local install](/developers/distribution-local-install).
