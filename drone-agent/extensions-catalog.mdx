These are the first-party extensions Altnautica publishes through the public [`ADOSExtensions`](https://github.com/altnautica/ADOSExtensions) repository. Each released extension ships as a signed `.adosplug` archive on GitHub Releases and installs from a node's **Extensions** page in Mission Control or with `ados plugin install`. Every extension is licensed GPL-3.0-or-later.

Each archive carries a `SIGNATURE` entry: the signer id and an Ed25519 signature over the archive's canonical payload hash (every entry except `SIGNATURE`). The agent verifies it against `/etc/ados/plugin-keys/<signer-id>.pem`, refuses a signer, archive or release (`<plugin_id>@<version>`) listed in `/etc/ados/plugin-revocations.json`, and refuses the install when no enrolled key verifies it. See [Signatures and trust](/drone-agent/plugins#signatures-and-trust).

The agent refuses an install on a board that is not in the extension's board list (`*` means any board).

## MAVLink Gimbal v2

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.mavlink-gimbal-v2` |
| Status | Released |
| Risk | medium |
| Type | Agent subprocess (Python) and Mission Control iframe |
| Hardware | A MAVLink gimbal-manager gimbal on component 154 |
| FC firmware | ArduPilot or PX4 forwarding the gimbal-manager messages |
| Resources | 64 MB RAM, 15% CPU, 8 processes |

Drives a MAVLink gimbal-manager on component 154. Beyond manual pitch and yaw it runs a visual servo on the companion: click a detected subject in the cockpit and the gimbal keeps it centred. It stops commanding the moment the vision engine reports the subject uncertain or lost, and it never re-locks onto a different subject by itself. Cockpit Skills: **Aim** (`G`), **Recenter** (`Shift+C`), **Nadir** (`Shift+V`) and **Rate mode** (`Shift+G`).

It speaks MAVLink Gimbal v2 only. A gimbal that does not present a gimbal-manager to the flight controller is not supported.

## Vision Navigation

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.vision-nav` |
| Status | Released |
| Risk | high |
| Type | Agent binary (Rust) and Mission Control iframe |
| Hardware | Downward USB UVC or CSI camera; optional rangefinder (TF-Luna on a companion serial port, or any rangefinder the flight controller publishes) |
| FC firmware | ArduPilot 4.5+, PX4 1.14+, iNav 7.0+ |
| Resources | 512 MB RAM, 80% CPU, 24 processes |

Position hold when GPS is unreliable. A downward camera plus the flight controller's gyro produce an optical-flow measurement about 30 times a second, sent as `OPTICAL_FLOW` to ArduPilot and iNav and as `OPTICAL_FLOW_RAD` to PX4. Three modes: optical flow with a rangefinder, optical flow without one (barometer height for scale, or GPS height in outdoor mode), or off. It does no visual-inertial odometry. The **Engage** Skill (`Shift+N`) turns it on and off.

<ExtensionVisionNav />

See the [Vision Navigation guide](/drone-agent/vision-nav-overview).

## Follow-Me

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.follow-me` |
| Status | Released |
| Risk | high |
| Type | Agent subprocess (Python) and Mission Control iframe |
| Hardware | USB UVC or CSI camera bound to the vision pipeline; a gimbal is optional |
| FC firmware | ArduPilot or PX4 in a guided position-hold mode (ArduPilot Copter Guided or Guided NoGPS, Plane and QuadPlane Guided, Rover Guided; PX4 Offboard) |
| Resources | 128 MB RAM, 25% CPU, 4 processes |

Click a subject in the live video and the drone follows it at a fixed distance and height. A detector on the companion produces detections, you designate one, and the companion locks that track, projects it onto the ground and streams guided position setpoints to the flight controller.

It stops commanding the instant the tracker reports the subject uncertain or lost, and never re-locks onto a different subject by itself. The **Follow-Me** Skill (`Shift+F`) arms and disarms the behaviour and asks for confirmation first. An AI client gets two tools, `follow_status` and `stop_follow`, and no way to start a follow: a follow begins only when an operator designates a subject.

<ExtensionFollowMe />

<Warning>
Follow-Me flies the drone with guided setpoints. Read [Safety](/operations/safety) before you use it.
</Warning>

## SIYI optical pod

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.siyi-pod` |
| Status | Released |
| Risk | high |
| Type | Agent subprocess (Python) and Mission Control iframe |
| Hardware | A SIYI pod (A2 mini, A8 mini, ZR10, ZR30, ZT6, ZT30) on the pod network (`192.168.144.x`) or a TTL serial port |
| Resources | 128 MB RAM, 25% CPU, 4 processes |

Speaks the SIYI Gimbal Camera External SDK over UDP, TCP or TTL serial, so the agent drives what a stock autopilot mount cannot: thermal palette and gain, the laser rangefinder and subject geolocation. On start it queries the firmware and hardware id, picks that model's capability profile, and exposes only the controls the model supports.

Until the pod answers the identity query it is sent nothing. The query retries on a fixed interval with no attempt limit, so a pod powered on after boot comes online without a restart. Laser range plus gimbal angles plus the flight controller's pose resolve a subject latitude and longitude, which the geolocate tool reports. Gimbal attitude and laser range are mirrored to the flight controller as standard MAVLink, so the built-in gimbal panel works too.

## Thermal camera

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.thermal-flir-lepton-usb` |
| Status | Development preview |
| Risk | medium |
| Type | Agent subprocess (Python) and Mission Control iframe |
| Hardware | FLIR Lepton 3.5 on a PureThermal 2 USB UVC dongle (firmware 1.2.2 or newer) |
| Resources | 192 MB RAM, 35% CPU, 16 processes |

Development preview: no release archive is published, and capture needs a native UVC backend that the agent does not supply. With no backend, no device on the bus or a failed open, the extension publishes an explicit unavailable state with the reason and never reports a temperature.

The driver targets a FLIR Lepton 3.5 on a PureThermal 2 dongle. It locks the radiometric linear mode so raw counts convert to degrees Celsius, meters a centre spot plus the frame minimum and maximum, and colourizes the feed with palettes that match between the agent and the cockpit overlay. Cockpit Skills: **Cycle palette** (`Shift+O`) and **Flat field correction** (`Shift+I`).

## World Engine

| Field | Value |
|---|---|
| Plugin id | `com.altnautica.world-engine` |
| Status | Released |
| Risk | high |
| Type | Agent binaries (Rust) on every profile and an inline Mission Control module |
| Hardware | Any camera the vision engine publishes frames for; a workstation or compute node on the drone's LAN |
| Profiles | `drone`, `ground_station`, `workstation`, `compute` |
| Resources | heavy class, 16 GB RAM, 800% CPU, 1024 processes |

Builds a 3D world model from a flight. The drone selects pose-tagged keyframes and streams them to a compute node on the same network, which reconstructs a Gaussian splat, point cloud, mesh and occupancy grid that Mission Control shows live and after landing. The same node runs perception offload for a drone with no on-board accelerator, returning detections to the drone's own detection bus.

The installer turns it on by default for workstation and compute nodes. Its binaries download at install for the node's own architecture, each checked against a SHA-256 pinned in the signed manifest.

<ExtensionWorldEngine />

See [World Engine](/drone-agent/extensions/world-engine) for setup, configuration and the API.

## Install one

From Mission Control:

1. Open the node, go to **Agent**, and under **Software** click **Extensions**.
2. Pick the extension from the list of available extensions and click **Install**, or click **Install from file** and upload a downloaded `.adosplug`.
3. Read the review page and click **Install**. The button names how many permissions the install grants.

See [Install extensions from Mission Control](/mission-control/installing-plugins).

From the agent CLI, `ados plugin install` takes a first-party catalog id, a release URL or a local archive:

```bash
ados plugin install com.altnautica.world-engine
ados plugin install https://github.com/altnautica/ADOSExtensions/releases/download/<tag>/<file>.adosplug
ados plugin install ./<file>.adosplug
```

A catalog id installs the version pinned in the agent's bundled catalog, which can lag the releases listed above. For the current release, install its URL. An id that is not in the bundled catalog installs only from its release URL or file. See [Extensions on the agent](/drone-agent/plugins).

## Publish your own

Build an extension with the SDK, sign it with your own key, and install it from a local file or a URL; see [Your first plugin](/developers/your-first-plugin) and [Distribution: local install](/developers/distribution-local-install). To list it in the registry, see [Distribution: the registry](/developers/distribution-registry).
