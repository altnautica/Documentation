## Pairing

The **Pairing** card shows one of two states:

- **paired:** the owner id and the time it was paired, plus an **Unpair** button.
- **awaiting pair:** the pairing code. The code is reported only while the node is unpaired, and only to a browser on the node's own networks. Elsewhere the card reads "The code is shown only on this node's own networks. Open the dashboard from the node's LAN, hotspot or USB link to read it."

How you pair depends on the cloud posture set in [Settings → Cloud](/drone-agent/dashboard-settings#cloud):

- **Local only (default):** in Mission Control open **Pair New Node** and enter the node's hostname or IP. Until then the PAIR tile on Home reads `n/a · local mode`.
- **Altnautica relay or self-hosted:** enter the code from this page in Mission Control, or use **Accept from Mission Control** below.

Once linked, the PAIR tile on Home and the Cloud Relay panel show the paired state.

## Accept from Mission Control

Shown only while the node is unpaired. Paste the code Mission Control shows into **Accept code from Mission Control** and press **Pair**.

This works in a cloud or self-hosted posture only. In local mode the agent refuses with `no_backend` and tells you to pair directly from Mission Control by hostname or IP instead.

## Phone receivers (ground station)

On a ground station the page adds a **Phone receivers** card. A phone with its own radio asks the ground station for the fleet receive keys, and nothing is shared until you approve it. Approve a phone only when the fingerprint shown matches the one on its screen. A phone receives video and telemetry; it never transmits. Each waiting phone has **Approve** and **Reject** buttons; with none waiting the card reads "No phone is waiting for approval."

## Unpair

Press **Unpair** and confirm **Unpair this drone?** (or **Unpair this ground station?**). Mission Control loses access until the node is paired again, and this dashboard asks for its PIN again.

## Data sources

| Endpoint | Used for |
| --- | --- |
| `GET /api/pairing/info` | pairing state, owner and code (every 5 s) |
| `POST /api/pairing/accept` | Accept from Mission Control |
| `POST /api/pairing/unpair` | Unpair |
| `GET /api/v1/ground-station/wfb/invite` | waiting phones (ground station) |
| `POST /api/v1/ground-station/wfb/invite/{id}/approve`, `.../reject` | phone decisions (ground station) |

  <Accordion title="No code is shown">

  </Accordion>
  <Accordion title="Accept says This device is already paired">
    Unpair first, then accept the new code.
