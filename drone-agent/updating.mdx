`ados update` re-runs the canonical installer in upgrade mode, which is the one path that updates the agent (the Rust services, the units and the CLI). Your device identity, config and pairing state are kept.

A node installed on the stable channel stays on stable; `--check-only` still reports main's version.

## What `ados update` does

The command compares the installed version with the version on `main`. If they differ, it fetches the latest `scripts/install.sh` and runs it with `--upgrade`, passing the profile recorded in `/etc/ados/profile.conf` so the upgrade cannot change what the node is. On the edge channel the installer reads the `prebuilt-main` release's `manifest.json`, which names the commit to install, and fetches the service binaries from that commit's `rev-<sha>` release, so the source and the binaries always match.

On a drone or ground station, the update is refused while the vehicle is armed or its arm state is unknown or stale, because an upgrade restarts the MAVLink, radio and video services. The command prints `Refusing to update` with the reason. Disarm first, or pass `--force-armed`; the installer's own preflight applies the same check and honours the same override.

- **Linux.** The installer re-runs as root (the command elevates with `sudo` when needed). It updates the Rust service binaries, the systemd units and the CLI, then restarts the agent.
- **macOS.** The installer runs without `sudo` and rebuilds the per-user install from source.

```bash
ados update
```

The command asks for confirmation before it installs.

## Flags

| Flag | What it does |
|---|---|
| `--check-only` | Report the installed version and the version on `main`. Installs nothing. |
| `--yes`, `-y` | Skip the confirmation prompt. |
| `--json` | Print `{current_version, latest_version, update_available}` and exit. |
| `--profile <drone\|ground-station\|workstation\|compute>` | Convert the node to another profile. By default the upgrade keeps the profile recorded in `/etc/ados/profile.conf`. |
| `--force-armed` | Update even while the vehicle is armed or its arm state is unknown. Passed through to the installer. |

### Check without installing

```bash
ados update --check-only
```

Example output:

```text
Current version: 0.102.5
Latest (main):   0.102.6
```

When the two versions match, `ados update` prints `Already up to date.` and exits.

### Update without a prompt

```bash
ados update --yes
```

### Machine-readable check

```bash
ados update --json
```

```json
{
  "current_version": "0.102.5",
  "latest_version": "0.102.6",
  "update_available": true
}
```

## Check the installed version

`ados version` prints the installed version. It works even when the agent services are down.

```bash
ados version
```

## Update with the install command

`ados update` wraps the installer's upgrade mode, so you can run the same upgrade by hand:

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh | sudo bash -s -- --upgrade
```

On macOS, run it without `sudo`.

## Pin a version or roll back

There is no rollback API. To move to a specific version, run the installer in upgrade mode with a pin. A signed stable release:

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh | sudo bash -s -- --upgrade --channel stable --version <X.Y.Z>
```

Or one commit on the edge channel, with that commit's prebuilt binaries:

```bash
curl -sSL https://raw.githubusercontent.com/altnautica/ADOSDroneAgent/main/scripts/install.sh | sudo bash -s -- --upgrade --channel edge --ref <commit>
```

Both keep `/etc/ados/config.yaml` and pairing state. The channel you pick is recorded in `/etc/ados/profile.conf` and used by later upgrades. See [Installer flags](/drone-agent/installation#installer-flags).

<Tip>
Test an update on a bench drone before you roll it out to a fleet. Run `ados update --check-only` to see the version on `main`, update the bench node, confirm it flies, then update the rest.
</Tip>
