A ground station is a Linux single-board computer, a WFB-ng USB radio for the drone link, and a USB-C power source. Everything else is optional.

## Required components

1. **A supported board.** See the table below.
2. **An RTL8812EU or RTL8812AU USB Wi-Fi adapter** for the WFB-ng receive path on 5 GHz.
3. **A USB-C power source** that sustains the board under radio load. Sizing is on [Power and runtime](/ground-agent/power-and-runtime).

## Tested ground-station boards

These boards carry a ground-station block in their hardware profile.

| Board | Default role | Roles | USB tether | HDMI kiosk | Local display |
|---|---|---|---|---|---|
| Raspberry Pi 4B | `direct` | direct, relay, receiver | Yes | Yes | I2C OLED, SPI LCD, or HDMI touch panel |
| Radxa Cubie A7Z | `receiver` | direct, relay, receiver | No | No | SPI LCD |

The Cubie A7Z profile does not include the video relay, USB tether or HDMI kiosk features. Use a Raspberry Pi 4B when the ground station itself must serve live video.

The Raspberry Pi 3 and the Radxa ROCK 5C Lite also carry a supported SPI LCD, see [Front panel](/ground-agent/display#supported-boards). The full board list for every profile is on [Drone Agent supported hardware](/drone-agent/supported-hardware).

## The radio adapter

The WFB-ng receive path needs an adapter that the agent recognises as a WFB radio: the RTL8812EU or the RTL8812AU, by USB ID or by driver.

<Warning>
Not every USB Wi-Fi adapter works. Generic "Wi-Fi 6" or "AC1200" adapters usually use a chipset without monitor-mode injection. The LB-LINK BL-M8812EU2 (RTL8812EU) is the reference adapter.
</Warning>

The RTL8812EU needs a DKMS kernel module, which the installer builds. If the build fails (usually missing kernel headers), the installer continues and reports it. Install the headers for your running kernel and re-run the installer with `--upgrade`.

## OLED display

Any SSD1306 or SH1106 I2C OLED at 128x64 or 128x32 works. The agent probes I2C address `0x3C`, then `0x3D`. Wire SDA, SCL, VCC (3.3 V) and GND. Controller and size settings are on [Front panel](/ground-agent/display#oled-status-display).

## GPIO buttons

Four momentary pushbuttons, each wired between a GPIO pin and GND. The agent enables internal pull-ups, so no external resistors are needed.

| Button | BCM GPIO | Header pin |
|---|---|---|
| B1 | GPIO 5 | Pin 29 |
| B2 | GPIO 6 | Pin 31 |
| B3 | GPIO 13 | Pin 33 |
| B4 | GPIO 19 | Pin 35 |

A board profile can declare other pins in a `buttons` block; these four are the fallback. What each button does is on [Front panel](/ground-agent/display#buttons).

## Gamepads

Any USB HID gamepad works in the on-box cockpit through the browser's Gamepad API. Pair Bluetooth gamepads from Mission Control (node panel, **Buttons** tab) or with the agent's Bluetooth routes (`POST /api/v1/ground-station/bluetooth/scan`, then `POST /api/v1/ground-station/bluetooth/pair`).

## Mesh hardware

A node in the `relay` or `receiver` role needs a **second RTL8812EU or RTL8812AU adapter** in another USB port. The first adapter stays on the drone link; the second carries the batman-adv mesh on 2.4 GHz (channel 1 by default). The agent counts WFB-class radios when it decides whether a node can join a mesh, so adapters with other chipsets do not qualify. A `direct` node needs no second adapter.

See [Local mesh (batman-adv)](/ground-agent/batman-adv).
