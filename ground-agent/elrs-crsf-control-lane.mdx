The ground station already receives video and telemetry from the drone over WFB-ng. The control lane adds an independent, low-bandwidth link the other way: the ground station drives an ExpressLRS (ELRS) transmitter module over USB serial and generates the RC link itself. WFB-ng stays the link for video and full-rate MAVLink.

<Warning>
A second link that moves the sticks is safety-critical. Validate your module, antennas and failsafe behaviour on the bench, read [Safety](/operations/safety), and confirm your setup meets the radio rules where you fly.
</Warning>

## Modes

A module runs one mode at a time, set by `radio.crsf.mode`:

| Mode | What the module carries |
|---|---|
| `crsf_rc` (default) | The 16 CRSF RC channels, sent to the drone's ELRS receiver. The lane also decodes the telemetry the module returns (link statistics, GPS, battery, attitude, flight mode). |
| `mavlink` | The module becomes a MAVLink carrier that the agent's MAVLink router ingests. It is telemetry only until `radio.crsf.mavlink_command_enabled: true`. The RC lane stands by. |
| `airport` | A raw serial data pipe. |

## Channel sources

In `crsf_rc` mode, `radio.crsf.channel_source` decides what feeds the channels:

| Source | Feeds the channels from |
|---|---|
| `hid` (default) | The primary gamepad or a USB handset, gated by the pilot-in-command (PIC) arbiter. |
| `inject` | Channel values set by software through `POST /api/v1/ground-station/crsf/channels`. Each write carries a time-to-live. |
| `hybrid` | The PIC holder decides: while a client holds PIC the lane obeys that client's source; with a fresh "no claim held" report, injected values feed. If the arbiter stops reporting, the lane falls back to the human path. |

A hobby handset running EdgeTX in "USB Joystick (HID)" mode works as a `hid` source: its own radio is off, and the ground station's module does the transmitting.

Neither source can hold a stale stick. When the winning source has no fresh sample, the lane stops sending RC frames, so the receiver and the flight controller run their own configured RC-loss failsafe. The lane never substitutes neutral values.

## Enable the lane

The lane is opt-in and runs only on the `ground_station` profile; on a drone it idles. Set the `radio.crsf` block in `/etc/ados/config.yaml`:

```yaml
radio:
  crsf:
    enabled: true
    device: /dev/ttyUSB0
    mode: crsf_rc
    channel_source: hid
    band: dual
    packet_rate_hz: 150
```

`device` must name the module's serial port; the lane never probes for one, and a pinned device is kept out of flight-controller discovery. `enabled` also writes the `/etc/ados/crsf-enabled` marker that the `ados-crsf` unit starts on.

## Surfaces

| Surface | Use |
|---|---|
| Mission Control | The **RC / ELRS Link** tab of the ground station's node panel appears when a CRSF module is present. |
| `GET /api/v1/ground-station/crsf` | Lane state, mode, channel source and link statistics. |
| `POST /api/v1/ground-station/crsf/channels` | Inject channel values (`inject` and `hybrid` sources). |
| `POST /api/v1/ground-station/crsf/params` | Send parameter requests to the module. |

The lane reports a link state like any other radio. Its state reads up only on received link statistics from the module, never on bytes sent. It carries no routed IP traffic and is not an internet uplink.

## Bands

| Band | Trade-off |
|---|---|
| 900 MHz | More range, lower MAVLink throughput |
| 2.4 GHz | More MAVLink throughput, less range |
| Dual-band | Both, on a dual-band module |

Range depends on the module, the antennas, the band and line of sight. The lane makes no fixed range claim.
