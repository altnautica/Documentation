This page takes one ground station from a fresh install to receiving a drone. To grow it into a relay and receiver mesh afterwards, continue with [Build a mesh](/ground-agent/mesh-setup).

## Before you start

- A board from [Ground Agent supported hardware](/ground-agent/supported-hardware).
- One RTL8812EU or RTL8812AU USB adapter for the drone link.
- Antennas: a 5 GHz antenna on the drone-link adapter. Keep at least 30 cm between antennas on the same chassis.
- Power, case and cabling. See [Power and runtime](/ground-agent/power-and-runtime).

The OLED, the LCD and the buttons are optional.

Add `--name <hostname>` to set a predictable mDNS name. Flags, upgrades and profile changes are on [Install the Ground Agent](/ground-agent/installation).

## Reach the node

Three ways in. All of them reach the agent on port `8080`.

| Path | Host |
|---|---|
| The ground station's Wi-Fi access point | `192.168.4.1` |
| USB tether | `192.168.7.1` |
| Your LAN | `<hostname>.local` |

From any of them, the node answers at these addresses (shown for the access point):

<GsEndpoints host="192.168.4.1" />

The access point broadcasts `ADOS-GS-<id>` and hands out addresses from `192.168.4.10` to `192.168.4.100`. Until setup finishes, joining it on a phone raises the operating system's sign-in sheet, which opens the setup wizard. If the sheet does not appear, open `http://192.168.4.1:8080` directly.

The access point passphrase is generated per unit. Read it on the box:

```bash
sudo ados network ap-passphrase
```

`<hostname>` is the node's system hostname, which avahi publishes. Set it with `--name` at install time, or read it with `hostname`.

For USB, connect a USB-C data cable from your laptop to the node's OTG port. The node takes `192.168.7.1` and gives your laptop `192.168.7.2`. See [USB tether](/ground-agent/usb-tether) and [Wi-Fi access point](/ground-agent/wifi-ap).

## Pick a role

Every ground station runs in one of three roles. The role is one config key, `ground_station.role`, and it decides which services start.

<CardGroup cols={3}>
  <Card title="direct" icon="circle-dot">
    Single-node receive. The default. No mesh services.
  </Card>
  <Card title="relay" icon="arrow-right-arrow-left">
    Forwards what it hears from the drone to a receiver over a local mesh.
  </Card>
  <Card title="receiver" icon="tower-cell">
    The hub. Combines what it hears with every paired relay's forwards and serves the stream.
  </Card>
</CardGroup>

| | `direct` | `relay` | `receiver` |
|---|---|---|---|
| Mesh services | off | on | on |
| Needs a second WFB-class adapter | no | yes | yes |
| Needs mesh pairing first | no | yes, with a receiver | no |
| Publishes mDNS `_ados-receiver._tcp` | no | no | yes |
| Default | yes | no | no |

**Pick `direct`** when one ground point sees the whole flight area. It needs the board, one radio adapter and antennas.

**Pick `relay`** to extend reception across an obstructed area: behind a hill, across a field, on the far side of a building. A relay listens to the drone with its own adapter and forwards what it heard over the mesh instead of decoding it. A receiver must already exist, and the relay must pair with it first.

**Pick `receiver`** for the node where the pilot and Mission Control sit. It combines its own reception with every relay's forwards and recovers what any one radio missed. There is exactly one receiver per mesh.

Setting `relay` or `receiver` is covered on [Build a mesh](/ground-agent/mesh-setup).

## Run the setup wizard

Open the reach URL and work down the steps. On a ground station with a cloud posture there are eleven steps; the default local-only posture hides the Mission Control pairing step, leaving ten. An optional step never blocks the finish.

<Steps>
  <Step title="Welcome">
    Confirms the device name, board and version, and shows which local networks are up (Wi-Fi, hotspot, USB tether or LAN). With no usable local network, this step asks you to bring one up first.
  </Step>
  <Step title="Profile">
    Confirms **Ground station** and the role.
  </Step>
  <Step title="Operating region">
    Optional. The agent defaults to an unrestricted RF posture. Pin a region here to enforce your jurisdiction's channel and power limits. While unpinned, local RF compliance is your responsibility.
  </Step>
  <Step title="Hardware check">
    Sweeps the components the role needs: the board, the radio adapter, a display, a gamepad, and the second adapter for mesh roles. Resolve anything reported missing before you continue; optional items can be skipped.
  </Step>
  <Step title="Cloud posture">
    The default is **local only**: Mission Control reaches the node over the LAN by hostname or IP and stores the key locally. Pick the cloud relay or a self-hosted backend only when you need access from another network.
  </Step>
  <Step title="Pair with Mission Control">
    Shown only for a cloud or self-hosted posture. See [Pair with Mission Control](#pair-with-mission-control).
  </Step>
  <Step title="Video">
    Confirms WHEP video is live. On a ground station, that means the received stream is being served.
  </Step>
  <Step title="Ground receiver">
    Confirms the WFB receive path and the drone pairing. See [Pair the air link](#pair-the-air-link).
  </Step>
  <Step title="Local display">
    Shown on every ground station. Sets up an attached SPI LCD and runs the nine-point touch calibration.
  </Step>
  <Step title="Remote access">
    Optional. Configure a tunnel for reaching the node from outside the local network.
  </Step>
  <Step title="Finish">
    Marks setup complete. The first-time sign-in responder on the access point stops from here on.
  </Step>
</Steps>

Once the node is in Mission Control, its node panel is the richest management surface: **Overview**, **Cockpit**, **Carried drones**, **Radio** (not on a receiver), **Network**, **Mesh & RX**, **RC / ELRS Link** (when a CRSF module is present), **Display**, **Buttons**, **Peripherals** and **Logs**. See [Ground station node panel](/mission-control/ground-station-panel).

## Pair with Mission Control

<PairingKinds />

**Local only** (the default): add the node in Mission Control by its hostname or IP over the LAN.

**Cloud or self-hosted**: the agent shows a six-character pairing code. Enter it in Mission Control to claim the node.

See [Connect Mission Control](/mission-control/connecting) and [Pairing](/drone-agent/pairing).

## Pair the air link

The air link is the WFB-ng key exchange between the drone and the ground station, separate from Mission Control pairing.

An unpaired ground station is armed for automatic pairing: a powered, unpaired drone in radio range pairs on its own, with no code. Live signal and bitrate appear once the drone is in range. The LCD **Pair drone** page and Mission Control's **Radio** tab show the paired drone and its key fingerprint.

After pairing:

- This ground station receives video only from drones that share its key.
- The pairing survives reboots and power cycles.
- Several drones can share one ground station's key; each takes its own fleet slot.

To pair with a different fleet, unpair first: the **Unpair** button on the LCD **Pair drone** page (two taps), Mission Control's **Radio** tab, or `DELETE /api/v1/ground-station/wfb/pair`. Unpairing wipes the station's radio keys for every drone.

Key material and the channel plan are on [WFB-ng pairing](/drone-agent/wfb-pairing).

## Verify

| Surface | What to look at |
|---|---|
| OLED | The third line reads `link <state> <rssi>dBm` once a drone is heard; the fourth line shows `role: direct`. |
| LCD | The **Radio link** and **Drone** tiles on the dashboard fill in. |
| Mission Control | The node card is online and the drone appears under **Carried drones**. |
| REST | `GET /api/v1/ground-station/status` |
| CLI | `ados diag link` for the radio verdict and `ados diag video` for the per-hop video verdict. |

On a working setup, video and telemetry appear within seconds of both sides powering up. Later flights need no setup steps.

## Re-run setup and reset

### Re-run the wizard

On the box:

```bash
curl -X POST http://localhost:8080/api/v1/setup/reset
```

Pairing keys and Mission Control links survive a wizard reset.

### Factory reset

Factory reset runs on the box only. A caller on loopback (or the operator socket) may reset; a remote caller is refused even with the pairing key. The `confirm` value is the installed drone key's fingerprint, which `GET /api/v1/ground-station/status` reports as `paired_drone.key_fingerprint`, or `factory-reset-unpaired` on a station that holds no key:

```bash
curl -X POST 'http://localhost:8080/api/v1/ground-station/factory-reset?confirm=<key-fingerprint>'
```

The reset, in order:

1. Moves the role to `direct`, which stops the mesh services. If that fails, nothing is wiped.
2. Unpairs the air link.
3. Deletes every standing credential, the device identity and `config.yaml`. `profile.conf` stays.
4. Deletes the mesh identity, revocations, role file and gateway pin.

The node does not reboot on its own. Reboot it afterwards; it comes back in its first-boot state with a fresh access point passphrase. The full wipe list is on [Hardening](/operations/hardening).
