Plug a USB-C data cable from the ground station to a laptop or Android phone. The board appears as a USB Ethernet adapter, so there are no drivers to install on current operating systems, and there is no Wi-Fi hop between you and the ground station.

## Before you start

- **Board.** USB tether works on the Raspberry Pi 4B through its USB-C port in device (OTG) mode. The Radxa Cubie A7Z does not support it.
- **Enable the USB device controller.** On a Raspberry Pi, add this line to `/boot/firmware/config.txt` and reboot. The installer does not set it.

  ```ini
  dtoverlay=dwc2,dr_mode=peripheral
  ```

- **A data-capable USB-C cable.** Many cheap cables carry power only.

## How it works

The uplink router (`ados-uplink-router`) composes a USB gadget with two Ethernet functions:

- **CDC-NCM**, native on current macOS, Windows 11, Linux and Android.
- **RNDIS**, for older Windows 10 builds.

Your computer picks the one it supports and gets a new network interface.

| Setting | Value |
|---|---|
| Ground station address | `192.168.7.1` |
| Laptop or phone address | `192.168.7.2` (DHCP) |
| Subnet | `192.168.7.0/24` |
| mDNS name | `<hostname>.local` |

## Platform notes

<Tabs>
  <Tab title="macOS">
    Plug in the cable. A new USB Ethernet interface appears in System Settings. Open `http://192.168.7.1:8080`.
  </Tab>
  <Tab title="Windows 11">
    Plug in the cable. A new Ethernet adapter appears in Network Connections. Open `http://192.168.7.1:8080`.
  </Tab>
  <Tab title="Windows 10">
    Usually works through the RNDIS function. If the adapter shows a yellow exclamation mark in Device Manager, update its driver and choose Microsoft's built-in "Remote NDIS Compatible Device" driver.
  </Tab>
  <Tab title="Linux">
    Both functions bind automatically and NetworkManager shows the new interface. If your distribution blocks LAN traffic by default, put the connection in a trusted firewall zone.
  </Tab>
  <Tab title="Android">
    Android 11 and later support CDC-NCM USB Ethernet. Plug in the cable; the phone takes `192.168.7.2` and reaches the ground station at `192.168.7.1`.
  </Tab>
</Tabs>

## Why use USB tether

| Advantage | Details |
|---|---|
| No airtime contention | No retries or interference to add jitter |
| No 2.4 GHz competition | Does not share spectrum with the access point or nearby networks |
| Wired reliability | No packet loss from Wi-Fi interference |
| Charging | Android phones can charge while tethered |

USB 2.0 has far more throughput than one video stream and telemetry need.

## Power and cables

<Warning>
If no network interface appears after you plug in, try another cable. Look for cables labelled for data.
</Warning>

On a Pi 4B the USB-C port carries both data and power. A laptop may back-power the board, but many laptops cannot supply enough current under radio and access point load, and brownouts follow. Power the ground station from its own wall adapter or power bank and use the tether cable for data. See [Power and runtime](/ground-agent/power-and-runtime).

## USB tether and Wi-Fi together

Both work at the same time: one client on USB for the pilot view, others on the access point to watch. The agent serves both subnets. With **uplink sharing** on, clients on either subnet get NAT internet through the active uplink; the two local subnets are still not bridged to each other.

## HTTPS caveat

A browser that loaded Mission Control over HTTPS blocks plain HTTP connections to `192.168.7.1`. Use the on-box surfaces at `http://192.168.7.1:8080`, or run Mission Control locally. See [Install Mission Control](/mission-control/installation).

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| No new network interface | Power-only cable | Use a data-capable USB-C cable. |
| No new network interface | USB device controller not enabled | Add `dtoverlay=dwc2,dr_mode=peripheral` to `/boot/firmware/config.txt` and reboot. `journalctl -u ados-uplink-router \| grep usb_gadget` shows whether the gadget was skipped. |
| Yellow exclamation mark on Windows | RNDIS driver not bound | Bind Microsoft's "Remote NDIS Compatible Device" driver in Device Manager. |
| Intermittent disconnects | Brownout from laptop power | Power the board separately. |
