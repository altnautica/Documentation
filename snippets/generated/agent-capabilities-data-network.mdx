| `cloud.publish` | data_network | medium | Yes | Lets the plugin publish small messages (at most 64 KiB each) on its own cloud stream through the agent's cloud relay, so a signed-in operator can receive them off the local network. | `cloud.read` | data_network | low | n/a | Lets the plugin read shared fleet data from the cloud backend (drone status rows, paired devices, fleet roster). |

| `event.publish` | data_network | low | Yes | Lets the plugin emit events on topics it has been granted access to. Other plugins and host services that subscribe to the same topic will receive the payload. |
| `event.publish` | data_network | low | n/a | Lets the plugin emit events on the in-memory GCS event bus other installed plugin panels subscribe to. The bus never leaves the browser tab; it carries no host authority of its own. |
| `event.subscribe` | data_network | low | Yes | Lets the plugin subscribe to topics it has been granted access to. The plugin sees payloads from other plugins and from host services that publish on those topics. |
| `event.subscribe` | data_network | low | n/a | Lets the plugin subscribe to topics on the in-memory GCS event bus and see payloads other installed plugin panels publish. |
| `mcp.expose` | data_network | medium | Yes | Lets the plugin publish its declared tools, resources, and prompts to an MCP client, and lets the host route a tool invocation into the plugin. Exposure alone grants no host authority: each tool acts only through the plugin's OTHER granted capabilities, so a tool can never do anything the plugin could not already do. |
| `mcp.expose` | data_network | medium | n/a | Lets the plugin publish its declared GCS-half tools, resources, and prompts to an MCP client. A GCS-only tool routes through the GCS bridge (command / mission), so its effect is still bounded by the plugin's other GCS capabilities and the MCP token's scope. |
| `network.listen` | data_network | high | Yes | Lets a declared plugin service bind the TCP ports it lists in its manifest (listen_ports) so other nodes on the network can reach it, and advertise those ports on the local network over mDNS through the agent. Every other port stays closed to the plugin, and the plugin's main process never listens. |
| `network.outbound` | data_network | medium | Yes | Lets the plugin make outbound TCP, UDP, and HTTP connections from the agent host, and find services on the local network over mDNS through the agent. Required by plugins that talk to external services. |

| `perception.subscribe` | data_network | low | n/a | Lets the plugin subscribe to the live detection stream (bounding boxes, classes, track ids) for the drones the operator has paired, the same detections the cockpit already renders. | `radio.aux_stream` | data_network | high | Yes | Lets the plugin open a dedicated auxiliary stream on the radio link (a separate radio-port from the data and control planes) managed by the radio service, and read or write application frames on it. | `recording.write` | data_network | low | n/a | Lets the plugin write recordings (video, telemetry CSV, analysis output) into the GCS recording library so the operator can replay them later. |
| `telemetry.extend` | data_network | low | Yes | Lets the plugin add new fields to the telemetry stream that ships to the GCS. Used by sensor plugins that surface custom readings on the dashboard. |

| `telemetry.subscribe` | data_network | low | n/a | Lets the plugin subscribe to live telemetry streams (attitude, GPS, battery, mode) for the drones the operator has paired with the GCS. |
| `video.source.set` | data_network | medium | Yes | Lets the plugin declare the camera and stream sources the agent's video pipeline should serve (one primary plus optional secondary legs), so a smart-camera or pod driver can auto-configure its own feeds without an operator hand-typing them. | `vision.detection.publish` | data_network | low | Yes | Lets the plugin publish detection results (bounding boxes, class labels, confidence, track ids) that other plugins, overlays, and mission logic can consume. Detections are derived data; they do not command the vehicle. |
| `vision.detection.subscribe` | data_network | low | Yes | Lets the plugin receive the detection batches the vision engine publishes (bounding boxes, class labels, confidence, and the tracker's stable track id and lock state on the locked object). Detections are derived data; subscribing does not command the vehicle or open the camera. |
