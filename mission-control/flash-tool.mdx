The **Flash Tool** flashes flight controller firmware, updates DroneCAN peripheral nodes and gives you the install command for the ADOS agents, all from one panel.

<Frame caption="Flash Tool on the Firmware step with the ArduPilot stack, a board and a Stable version selected.">
  ![Flash Tool Firmware step with the ArduPilot stack, CubeOrangePlus board, ArduCopter Stable version and flash methods](/images/mission-control/flash-tool.png)
</Frame>

## Open the Flash Tool

- **Settings** → **Flash Tool** (route `/config/firmware`)
- The ⚡ **Flash Tool** button in the top bar
- A node's **Setup** tab → **SYSTEM** → **Firmware**

Links can preselect a stack and an AP_Periph node with `/config/firmware?stack=<stack>&target=<node id>`, for example `?stack=ap-periph&target=10`.

## Choose a stack

| **Firmware Stack** | Target | Flash path |
|---|---|---|
| ArduPilot | Flight controller | ArduPilot bootloader over USB, USB DFU or ST ROM (UART) |
| Betaflight | Flight controller | USB DFU or ST ROM (UART) |
| PX4 | Flight controller | PX4 bootloader over USB, or USB DFU |
| AP_Periph (CAN nodes) | DroneCAN peripheral | DroneCAN firmware update over SLCAN or through the agent |
| ADOS Drone Agent | Companion computer | Install command |
| ADOS Ground Agent | Companion computer | Install command |

Mission Control does not flash iNav. Use iNav Configurator, then connect the board to Mission Control to configure it.

<Note>
Flashing needs WebUSB (DFU) and Web Serial (bootloader paths): Chrome or Edge on desktop, or the [desktop app](/mission-control/desktop-app). Firefox and Safari support neither. The agent install command works in any browser because it runs on the board.
</Note>

## Flight controller firmware

### Flash methods

Pick a **Flash Method**, or leave it on **Auto**.

| Stack | Method | What it does |
|---|---|---|
| ArduPilot | **Auto** | ArduPilot bootloader over USB; USB DFU only when a DFU device is present |
| ArduPilot | **Bootloader (USB)** | ArduPilot bootloader over USB with the `.apj` image |
| ArduPilot | **USB DFU** | STM32 USB DFU with the `_with_bl.hex` image |
| ArduPilot | **ST ROM (UART)** | ST ROM bootloader over a UART with BOOT0 held |
| Betaflight | **Auto** | USB DFU, then the ST ROM bootloader on the same port |
| Betaflight | **USB DFU** | Native USB DFU |
| Betaflight | **ST ROM (UART)** | ST ROM bootloader over a UART with BOOT0 held |
| PX4 | **Auto** | PX4 bootloader over USB |
| PX4 | **PX4 Bootloader** | PX4 bootloader (the `px_uploader` protocol) |
| PX4 | **USB DFU** | Native USB DFU, for absolute `.hex` images only |

### Flash ArduPilot

<Steps>
  <Step title="Connect the flight controller">
    Plug it in over USB. If it is connected in Mission Control, the panel shows **FC Connected via MAVLink** and the board details from `AUTOPILOT_VERSION`. A board already in bootloader mode shows **DFU Device Connected**.
  </Step>
  <Step title="Pick the firmware">
    Choose the **Vehicle Type** (ArduCopter, ArduPlane, ArduRover or ArduSub) and the **Version**: a stable release (marked Recommended), **Latest Beta**, **Latest Build** or **Development (Unstable)**. Check that the board target matches your hardware.
  </Step>
  <Step title="Confirm the checklist">
    Tick the pre-flash checklist. **Flash Firmware** stays disabled until every item is ticked.
  </Step>
  <Step title="Flash">
    Click **Flash Firmware**. The board reboots into its bootloader and the progress bar tracks the write. Do not unplug the board.
  </Step>
  <Step title="Reconnect">
    The board reboots into the new firmware. Reconnect and check the version in the board details.
  </Step>
</Steps>

PX4 and Betaflight follow the same flow with their own target and version pickers. A Betaflight board that cannot reboot into DFU from software needs its boot button held while you plug in USB.

<Warning>
Flashing the wrong target can leave the flight controller unbootable until you reflash it in DFU mode. Always check the detected board against the target you pick.
</Warning>

### Pre-flash checklist

| Stack | Items |
|---|---|
| ArduPilot, Betaflight, PX4 | I have backed up my parameters. All propellers are removed. Flight battery is disconnected (USB power only). |
| AP_Periph | Props removed from any prop-driving nodes. Drone disarmed. I understand the node will reboot mid-flash. |
| ADOS agents | Data on the board's storage will be erased. Board is powered via USB only (no external supply). I have backed up any user data on the board. |

### DFU mode

| Way in | When |
|---|---|
| Software reboot to bootloader | Most boards. The Flash Tool triggers it |
| Boot button | Hold it while plugging in USB, for example when the firmware no longer responds |
| Boot pads | Some boards need two pads shorted at power-on. Check the board's documentation |

## AP_Periph CAN nodes

The **AP_Periph (CAN nodes)** stack flashes AP_Periph firmware to DroneCAN peripheral nodes such as GPS, compass and airspeed units on the CAN bus.

<Steps>
  <Step title="Choose the transport">
    Under **Connection**, pick **SLCAN** (needs a direct USB connection to the flight controller) or **CAN_FORWARD (via agent)**, which routes CAN frames through the connected Drone Agent.
  </Step>
  <Step title="Pick the target node">
    **Target node** lists the DroneCAN nodes on the bus with their ID, name and software version. Select the node to update.
  </Step>
  <Step title="Confirm and flash">
    Tick the AP_Periph checklist and flash. The node reboots during the update.
  </Step>
</Steps>

The **DroneCAN** panel (Setup → **DEBUG**) shows the nodes on the bus and links a node straight to this stack.

## Back up and restore parameters

Back up before every flash: a major firmware upgrade can reset parameters.

- **Backup Parameters** in the Flash Tool saves the flight controller's parameters to a file.
- **Restore Parameters** loads a backup, compares it with the flight controller and writes the values you select with **Restore**. It is disabled while the aircraft is armed.

You can also export from the [Parameters](/mission-control/parameters) tab and load the file with **Compare** after the flash. Some parameters change name or meaning between firmware versions, so review the diff before writing.

## Companion computers

The **ADOS Drone Agent** and **ADOS Ground Agent** stacks install the agent on a companion computer that already runs a stock OS (Raspberry Pi OS, Radxa OS, Ubuntu and similar).

<Frame caption="Flash Tool with the ADOS Drone Agent stack, a target board selected and the install command card.">
  ![Flash Tool ADOS Drone Agent stack showing the target board picker and the Install on a board running stock OS card](/images/mission-control/flash-tool-agent.png)
</Frame>

<Steps>
  <Step title="Pick the stack and board">
    Choose **ADOS Drone Agent** or **ADOS Ground Agent**, then your board. The board list matches [Supported hardware](/drone-agent/supported-hardware).
  </Step>
  <Step title="Copy the command">
    The **Install on a board running stock OS** card shows the install command for that stack. Click **Copy**.
  </Step>
  <Step title="Run it on the board">
    SSH into the board and paste the command. The installer detects the board, installs the agent and its services, and starts them.
  </Step>
  <Step title="Check the agent">
    Run `ados status` on the board.
  </Step>
</Steps>

The command for the Drone Agent is the standard installer. The Ground Agent command adds the ground-station profile. See [Drone Agent installation](/drone-agent/installation) and [Ground Agent installation](/ground-agent/installation) for the flags.

### Add the board to your fleet

When the agent is running, open `http://<board-ip>:8080` to finish its setup. Then in Mission Control click **+** at the top of the Fleet sidebar and add the board by hostname or IP in the **Companion Computer** column of the Connect dialog. See [Pairing](/drone-agent/pairing) or, for a ground station, [Set up a ground station](/ground-agent/setup).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Board not detected">
    Check that the flight controller is powered and connected with a data-capable USB cable. On Linux, your user needs serial port access (the `dialout` group).
  </Accordion>
  <Accordion title="Flash fails partway">
    Do not unplug the board. Try again. If the firmware no longer boots, enter DFU mode with the boot button and reflash. The bootloader is separate from the firmware and is not overwritten.
  </Accordion>
  <Accordion title="Parameters reset after flashing">
    Restore your backup with **Restore Parameters** and review the diff.
  </Accordion>
  <Accordion title="The install command fails on the board">
    Check that the board has internet access. Behind a proxy, set `http_proxy` and `https_proxy` before running the command. See [Drone Agent troubleshooting](/drone-agent/troubleshooting).
  </Accordion>
</AccordionGroup>
