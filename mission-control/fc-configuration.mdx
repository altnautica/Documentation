A node's **Setup** tab configures its flight controller. The left sidebar lists panels in sections (**FLIGHT**, **SAFETY**, **SENSORS**, **TUNING**, **DISPLAY**, **SYSTEM**, **SECURITY**, **DEBUG**, **PROGRAMMING**). Mission Control shows only the panels the connected firmware and vehicle support.

<Frame caption="Setup tab with Flight Modes open on a landed, disarmed ArduPilot copter.">
  ![Setup tab with the FLIGHT section expanded and the Flight Modes panel showing the current mode, the mode switch channel and six mode slots](/images/mission-control/setup-flight-modes.png)
</Frame>

## How panels work

1. **Read from FC** loads the panel's parameters. **Refresh** reloads them.
2. Edit values. Changed values are highlighted, and leaving a panel with unsaved changes asks first.
3. **Save** writes the changes to the flight controller.
4. **Write to Flash** stores them across reboots. ArduPilot and PX4 already store each parameter as it is written; Betaflight and iNav need the explicit save.

When a change needs a reboot, a banner offers **Reboot Now**.

| Shortcut | Action |
|---|---|
| `Ctrl+S` | Save the panel's changed parameters |
| `Ctrl+Shift+S` | Write to flash |
| `Ctrl+R` | Refresh the panel |

`Ctrl` is `⌘` on macOS.

### While the aircraft is armed

Each panel shows an amber banner: **Vehicle is armed. Parameter changes write live, so review before saving.** Parameter writes still work, but each write opens a **Vehicle is armed** dialog listing the parameters; click **Write Anyway** to send them. A small set of controls is disabled while the aircraft is armed, and stays disabled until the flight controller reports it is disarmed: motor and servo tests, ESC calibration, every sensor and RC calibration start, frame-class changes and reset to defaults. The disabled control says why.

<Warning>
Armed writes take effect immediately and can change how the aircraft flies. Disarm before configuring. See [Safety](/operations/safety).
</Warning>

## How a panel is chosen

Each panel can declare up to five gates, and all must pass:

- a firmware capability (for example MAVLink signing support),
- the vehicle classes it applies to (copter, plane, VTOL, rover, sub),
- a specific vehicle type (for example a traditional helicopter),
- firmwares it is hidden on,
- whether it configures the companion agent instead of the flight controller.
