Mission Control is a Next.js application. You can use the hosted version at [command.altnautica.com](https://command.altnautica.com), install the [desktop app](/mission-control/desktop-app), or run it from source as described here.

## Requirements

| Requirement | Value |
|---|---|
| Node.js | 20 or newer |
| Browser | Chrome or Edge for USB Serial and Bluetooth. Other browsers can use the network methods only. |
| Shell | macOS or Linux shell, or Git Bash or WSL on Windows |

<Note>
The npm scripts use POSIX shell syntax (`rm -rf`, `cp -R` and inline `VAR=value`). On Windows, run them from Git Bash or WSL; they fail in cmd and PowerShell.
</Note>

## Run from source

<Steps>
  <Step title="Clone the repository">
    ```bash
    git clone https://github.com/altnautica/ADOSMissionControl.git
    cd ADOSMissionControl
    ```
  </Step>
  <Step title="Install dependencies">
    ```bash
    npm install
    ```
  </Step>
  <Step title="Start the dev server">
    ```bash
    npm run dev
    ```
    The server listens on port 4000.
  </Step>
  <Step title="Open it">
    Go to [http://localhost:4000](http://localhost:4000). The Dashboard opens. On first run a setup wizard asks for language, accepts the operator disclaimer, and sets units, region and theme.
  </Step>
</Steps>

## Demo mode

Demo mode replaces real links with a simulated fleet, so every panel has something to show.

```bash
npm run demo
```

`npm run demo` sets `NEXT_PUBLIC_DEMO_MODE=true` and starts the dev server on port 4000. You can also add `?demo=true` to any Mission Control URL, or turn **Demo Mode** on in **Settings → General**. The simulated nodes are listed on [Dashboard and fleet](/mission-control/dashboard#demo-fleet).

## npm scripts

| Command | What it does |
|---|---|
| `npm run dev` | Dev server on port 4000 with Turbopack. No demo data. |
| `npm run demo` | Dev server on port 4000 with the demo fleet. |
| `npm run build` | Production build. |
| `npm run start` | Serve the production build on port 4000. |
| `npm run copy:cesium` | Copy the Cesium assets into `public/cesium`. Runs before `dev`, `demo` and `build`. |
| `npm run lint` | ESLint. |
| `npm run typecheck` | Type-check the app, the Convex functions, the Electron main process and the bundled tools. |
| `npm test` | The Vitest suite. |
| `npm run test:node` | The `*.node-test.ts` files under the Node test runner. |
| `npm run convex:dev` | Start the Convex dev backend and code generation. |
| `npm run convex:deploy` | Deploy the Convex functions. |
| `npm run deploy` | Run the self-host deploy tool. See [Deploy tool](/developers/self-hosting/deploy-tool). |
| `npm run desktop:dev` | Run the desktop app against the dev server. Build commands are on [Desktop app](/mission-control/desktop-app#build-from-source). |

There is no browser end-to-end test harness in the repository.

Cesium assets are self-hosted from `/cesium/`, copied from `node_modules` by `npm run copy:cesium` before dev, demo and build, so the 3D mission preview works offline.

## Environment variables

Every variable is optional. Mission Control runs standalone with none of them set. `.env.example` in the repository is the reference. The variables split in two because two different runtimes read them.

### Next.js variables

Set these in `.env.local` in the project root.

| Variable | Effect |
|---|---|
| `NEXT_PUBLIC_DEMO_MODE` | `true` starts in demo mode. `npm run demo` sets it for you. |
| `NEXT_PUBLIC_CONVEX_URL` | Your Convex deployment URL. Enables sign-in, cloud fleet and community features. |
| `GITHUB_TOKEN` | Raises the PX4 releases API budget from 60 to 5000 requests an hour. Read server-side only; no scopes are needed. Prefer exporting it in your shell over writing it to a file. |
| `GROQ_API_KEY` | Enables AI PID tuning suggestions. |
| `NEXT_PUBLIC_ANALYTICS_SCRIPT_URL` | Script URL for any cookieless script-tag analytics. Off by default. |
| `NEXT_PUBLIC_ANALYTICS_WEBSITE_ID` | Site id for the same. Both analytics variables must be set or the script does not load. |

### Convex server variables

These run inside Convex functions, not in Next.js, so a `.env` entry does nothing for them. Set them in the Convex dashboard under Settings, Environment Variables, or from the CLI:

```bash
npx convex env set KEY value
```

| Variable | Effect |
|---|---|
| `JWT_PRIVATE_KEY` | RSA private key for signing session tokens. `npx @convex-dev/auth` sets it. |
| `JWKS` | JSON Web Key Set for token verification. Same setter. |
| `SITE_URL` | The public origin you serve Mission Control from, for example `https://mc.example.com`. |
| `ADOS_BOOTSTRAP_ADMIN_EMAILS` | Comma-separated emails. When the first profile is created and its email is on this list, it becomes admin. |
| `ADOS_ALLOW_FIRST_USER_ADMIN` | `1` makes the first profile admin when `ADOS_BOOTSTRAP_ADMIN_EMAILS` is empty. Ignored when the list is set. |
| `CESIUM_ION_TOKEN` | Cesium ion token for 3D terrain in the mission preview. |
| `GROQ_API_KEY` | AI changelog summaries and PID tuning. |
| `GITHUB_TOKEN` | GitHub API access for changelog sync. |
| `AI_PID_WEEKLY_LIMIT` | Maximum AI PID analyses per user per week. Default 3. |
| `MQTT_BROKER_URL` | MQTT WebSocket URL for cloud telemetry, for example `wss://mqtt.example.com/mqtt`. |
| `VIDEO_RELAY_URL` | Video relay WebSocket URL, for example `wss://video.example.com`. |
| `VIDEO_RELAY_SECRET` | Shared secret the video relay also holds. Used to mint its short-lived viewer tokens. |

Without either admin variable, every new profile stays `pending` until an existing admin approves it. Role details are on [Cloud features](/mission-control/cloud-features#sign-in-and-roles).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Port 4000 is already in use">
    The npm scripts pin port 4000, so `PORT` is ignored. Free the port, or start Next.js on another port directly:
    ```bash
    npm run copy:cesium && npx next dev --turbo --port 4001
    ```
  </Accordion>
  <Accordion title="USB Serial shows Chrome or Edge">
    Web Serial and Web Bluetooth exist only in Chromium browsers. Use Chrome or Edge, or the desktop app.
  </Accordion>
  <Accordion title="Sign-in shows Cloud Not Available">
    `NEXT_PUBLIC_CONVEX_URL` is not set in this build. Set it and restart the dev server, or choose **Continue in local mode**. Everything except the cloud features works without it.
  </Accordion>
  <Accordion title="npm run dev fails on Windows">
    Run it from Git Bash or WSL. The scripts use POSIX shell commands.
  </Accordion>
</AccordionGroup>
