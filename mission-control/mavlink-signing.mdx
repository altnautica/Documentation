With signing on, every command Mission Control sends to the flight controller carries a signature made with a key held in your browser. The flight controller rejects commands it cannot verify, so no other client can impersonate you. The key lives only in your browser, not on the companion computer.

This page covers the operator flow. For the protocol and the agent routes, see [MAVLink signing in the Drone Agent](/drone-agent/mavlink-signing).

## Where to find it

Select the drone, open its **Setup** tab and choose **SECURITY** → **MAVLink Signing**.

## Firmware support

| Firmware | Status |
|---|---|
| ArduPilot | Supported |
| PX4 | Not available. PX4 has no persistent on-board signing key store |
| Betaflight | Not applicable. MSP has no signing |
| iNav | Not applicable. MSP has no signing |

On an unsupported firmware the panel shows **Signing not available on this drone**.

## Enable signing

<Steps>
  <Step title="Open the panel">
    The panel shows **MAVLink signing is off** with **Enable signing** and **Import an existing key**.
  </Step>
  <Step title="Click Enable signing">
    The browser generates a random 32-byte key, enrols it with the flight controller (`SETUP_SIGNING`), and stores it in this browser. The panel shows **Signing enabled** and a short **Key fingerprint** you can compare later.
  </Step>
</Steps>

Enforcement starts at enrolment; ArduPilot has no separate require switch. Once it holds a key, it accepts unsigned commands only on its USB port and rejects them on every other link.

<Warning>
Signing can lock you out. If you lose every browser that holds the key, the flight controller rejects every command except over USB. Export a copy of the key before enabling signing on an aircraft you cannot reach physically.
</Warning>

## When the flight controller has not confirmed

The flight controller never acknowledges a signing change, so the panel asks you instead of guessing.

- **Interrupted enrolment or rotation.** If a request fails after the key may have gone out, the browser keeps both the new and the previous key, signs with the new one, and shows that the flight controller may hold either. Send a command: if it is accepted, choose **It has the new key**; if it is rejected, choose **It kept the previous key**.
- **Disable.** **Disable signing** sends an all-zero key, then keeps your key and keeps signing until you confirm. Once the flight controller accepts unsigned commands on a link other than USB, choose **Signing is off: forget the key**. If it still rejects them, choose **It is still signing: keep the key**.

## Rotate a key

Click **Rotate key** and confirm. The browser generates a new key, enrols it, and replaces the old one. Other browsers that held the old key stop working for that drone until they import the new one. A reminder with **Rotate now** appears when a key has been in use for a long time.

## Import a key

If you have the key from another browser or ground station, click **Import an existing key** and paste the 64-character hex string. The browser stores and signs with it. Nothing is enrolled or tested: the key must already be on the flight controller, and the next command shows whether it is.

## Export a key

**Export key** rotates to a fresh key and copies it to your clipboard for 60 seconds (**Rotate and copy**). It never appears on screen. The new key is stored in this browser before the clipboard is touched; if the browser refuses the clipboard write, the panel offers **Copy again**. Exporting again replaces the key.

## How the key is stored

The key is stored as raw bytes in this browser's IndexedDB (`signing-keys-v1`), tagged with the drone and, when you are signed in, your user id. MAVLink signing hashes the key itself with SHA-256, which Web Crypto cannot do with a non-extractable key, so any script on the Mission Control page can read it. Treat the browser profile as holding the key, and rotate it if you suspect the browser or site is compromised.

- Signing out purges the records tagged with your user id. Records enrolled while signed out stay on the device.
- Private and incognito windows lose their IndexedDB when closed. Use a normal window for signing.
- Cloud key sync is off: each browser keeps its own keys. Move a key between browsers with export and import.

## Troubleshooting

If commands stop working after enabling signing:

1. Try over USB. If commands work there, the flight controller holds a key this browser does not sign with, usually because another browser rotated it.
2. Import the current key from the browser that holds it, or connect over USB and enable signing again from this browser to enrol a new key.

If you cannot reach the panel, a paired client on the LAN can clear the flight controller's key through the agent:

```bash
curl -X POST http://192.168.1.50:8080/api/mavlink/signing/disable-on-fc \
  -H "X-ADOS-Key: <pairing-key>"
```

The agent answers `503` when the flight controller is not connected, refuses the call while the aircraft is armed, and does not accept it over the cloud relay.
