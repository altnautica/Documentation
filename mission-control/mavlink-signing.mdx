# MAVLink Signing

Every outgoing command to a signing-enabled drone carries an HMAC-SHA256 tag your browser generated. The flight controller rejects anything it cannot verify. Nobody else can impersonate you, and the agent running on the companion computer cannot forge commands either: the key lives only in your browser.

This page covers the operator flow. For the protocol detail and agent REST surface, see [MAVLink Signing in the Drone Agent guide](/drone-agent/mavlink-signing).

## Where to find it

Select a drone in the fleet sidebar, open the Configure tab, and pick the Security section on the left. The MAVLink Signing panel is the first entry.

The fleet sidebar shows a small pill next to each drone with the current state: Signed, Unconfirmed while a key change waits for you to confirm it, Unsigned, or No signing when the firmware does not expose a signing key store.

## Enabling signing

<Steps>
<Step title="Confirm capability">
The panel asks the agent which autopilot the flight controller reports. ArduPilot is supported. PX4, Betaflight, and iNav show a muted "not available" card.
</Step>
<Step title="Click Enable signing">
The browser generates a 32-byte random key, enrolls it with the flight controller via `SETUP_SIGNING`, and stores the key locally. The panel shows a short fingerprint so you can verify the key identity later.
</Step>
</Steps>

Enforcement starts with enrollment. There is no separate require switch: ArduPilot has no such parameter. Once it holds a key it accepts unsigned commands only on its USB port and rejects them on every other link.

<Warning>
Signing can lock you out. If you lose every browser that holds the key, the flight controller rejects every command except over USB. Export a copy of the key, or import it into a second browser, before enabling signing on a drone you cannot physically reach.
</Warning>

## When the flight controller has not confirmed

The flight controller never acknowledges a signing change, so the panel does not guess at one.

- **Interrupted enrollment or rotation.** If the request fails after a key frame may have gone out, the browser keeps both the new key and the previous one, signs with the new one, and shows an Unconfirmed card. Send a command: if it is accepted, choose `It has the new key`; if it is rejected, choose `It kept the previous key`.
- **Disable.** `Disable signing` sends the flight controller an all-zero key and then keeps your key, still signing, until you confirm. Once the flight controller accepts unsigned commands on a link other than USB, choose `Signing is off: forget the key`. If it still rejects them, choose `It is still signing: keep the key`.

## Rotating a key

Open the Signing panel, click `Rotate key`, confirm. The browser generates a fresh 32-byte key, enrolls it with the flight controller, and replaces the previous one once the agent reports the new key sent. The flight controller now trusts the new key exclusively.

Other browsers that held the old key stop working for that drone until you re-enroll them. Each browser handles its own keys; there is no automatic cross-browser sync today.

## Key storage in this browser

Raw key bytes exist in memory only at generation time and during the one-shot POST to the agent. The browser imports the bytes as a Web Crypto `CryptoKey` with `extractable: false`. That handle can sign and verify frames, but `crypto.subtle.exportKey` throws `InvalidAccessError` on it. Even an XSS payload on the same page cannot exfiltrate the raw key, only use it while the session is open.

The CryptoKey handle is stored in IndexedDB under the `signing-keys-v1` object store, tagged with the drone id and the signed-in user id when you are authenticated.

<Info>
If you sign out and someone else signs in on the same browser, the signing records tagged with your user id are purged automatically. Anonymous records (enrolled while signed out) stay on the device.
</Info>

## Private browsing

IndexedDB in private or incognito windows is scoped to the window session. Signing keys enrolled in a private window vanish when you close it. For durable signing, use a regular browser window, or pair a second browser and rotate a copy across.

## When signing is not available

Firmware compatibility table:

| Firmware | Status |
|---|---|
| ArduPilot | Supported |
| PX4 | Not available today. PX4 supports the protocol but lacks a persistent on-board key store. |
| Betaflight | Not applicable. MSP has no signing concept. |
| iNav | Not applicable. MSP has no signing concept. |

The panel shows a muted card explaining the reason. The fleet sidebar badge renders differently from `Unsigned` so operators can distinguish "feature off" from "feature not available".

## Bringing your own key

If you already have a MAVLink signing key from another browser, an export, or another ground station, click `Import an existing key` in the Signing panel and paste the 64-character hex string. The browser imports it as a non-extractable CryptoKey and signs with it. No enrollment happens and nothing is tested: the key must already be on the flight controller, and the next command from this browser shows whether it is.

## Exporting a key

`Export key` rotates to a fresh key and copies the new key to your clipboard for 60 seconds; it never appears on screen. The new key is stored in this browser before the clipboard is touched. If the browser refuses the clipboard write, the panel keeps the key and offers `Copy again`. Closing that dialog without copying leaves the key working in this browser, but it cannot be exported again without another rotation.

## Troubleshooting

If commands suddenly stop working after enabling signing:

1. Check whether they still work over USB. If they do, the flight controller holds a key this browser does not sign with, usually because another browser rotated it.
2. Import the current key from the browser that holds it, or re-enroll from this browser over USB.

If you are locked out entirely, clear the flight controller's signing store with `Disable signing` from a browser that still holds the key, or connect over USB and enable signing again from this browser, which enrolls a new key.

If you cannot reach the panel, the same action is available as a direct agent call:

```bash
curl -X POST http://drone-ip:8080/api/mavlink/signing/disable-on-fc \
  -H "X-ADOS-Key: your_key"
```

The agent gates this on the flight controller being connected and answers `503` if it is not.
